# LNS 等价计算加速结果

## 结论

本轮选择并只优化了一个热点：原 LNS 修复中每个插入方案重复执行的四路线 `_loads()` 与 `_directed_proxy()`。新路径在固定迭代下与旧路径逐候选完全等价，并在 12 组真实 60 秒 development 配对中取得 **3胜 / 9平 / 0负**；配对 Cmax 相对变化中位数 **0.00%**、均值 **−1.82%**、最差恶化 **0.00%**。因此属于“等价加速有效”：保留为显式可选路径，但默认生产开关仍关闭，须用新的未参与开发 workbook 独立验证后才能切换默认。

加速没有解决搜索空间本身的停滞。N85 四组全部持平；相对既有 HGA/WAG 约 18%–19% 的正式差距，开发集平均 1.82% 的改善远不足以宣称追平。下一阶段应冻结本轮实现并进行新独立验证；若仍持平，剩余问题是搜索空间/强初值后的结构性下降能力，而不是继续做无依据微优化。

## 1. 实测热点

用 REGION 初始化、HEURISTIC、144 atomic + 48 原 LNS、CRRR 关闭，在三个 consumed-development 实例各执行一个固定迭代。下列时间存在包含关系：LNS destroy/repair 是候选生成的一部分，不能与候选生成相加。

|实例|候选生成(s)|其中 LNS destroy/repair(s)|direction(s)|B32/reference(s)|LNS 插入评价|
|---|---:|---:|---:|---:|---:|
|N35-S1|1.295|0.397|0.005|1.623|11,144|
|N55-I5|5.368|4.112|0.008|2.317|85,880|
|N85-I9|4.437|2.657|0.010|4.530|37,376|

结论不是“所有实例都由 LNS 主导”：S1 与 I9 的 B32 仍很昂贵；但 I5 的 LNS 修复占候选生成约 77%，I9 也占约 60%，且该处存在明确、无需改变搜索决策的重复几何计算。B32 没有同等安全的等价重构空间，因此未修改。

## 2. 实际修改

- `SearchConfig.lns_incremental_scoring` 为显式开关，默认 `False`；旧生产轨迹不变。
- `_parent_alternatives()` 只在开关启用时缓存四条路线的加工时间项和相邻弧成本。
- 插入一个 block 时，只重算受影响机器人的负载项和插入点附近一至两条有向空走弧；第二个 Y/X child 基于第一个 child 插入后的真实中间路线继续更新，包含同机器人前插/后插情形。
- `_proxy_from_arc_costs()` 仍按原机器人、原弧顺序逐项累加，避免“先求每条路线小计”改变浮点结合顺序和边界 tie。
- `_insert_one()`、destroy/repair operator、Regret-2 最好/第二好规则、candidate identity、provenance、family、C2/C4、SA、direction、B32 和 certifier 均未改变。
- M192、144/48、Kdp8、Kref2/Kref_total4、插入上限和 `repair_evaluation_cap` 均不变；CRRR、CRRR_ACCESS_C2、TWO_OPT_STAR 继续关闭。

## 3. 等价验证

单元级覆盖 WHOLE、mandatory Y 的两个 child、同机器人不同插入顺序、X_SPLIT 固定 child 机器人、正反方向、空路线和首/中/尾插入、Greedy/Regret-2、评价硬上限、identity/provenance。旧/新增量 `_InsertionAlternative` 和 `RepairResult` 直接作严格相等比较。

原生 N35-S1、N55-I5、N85-I9 固定 seed `20261801`、固定一个完整迭代的回放逐项相同：48 个 LNS 结果与顺序、完整 M192 有效候选身份/顺序、C2 Top8、direction、C4 Top2、B32 状态、认证结果、SA 接受、best Cmax 序列及最终 canonical solution 全部一致。不是“最终 Cmax 接近”，而是搜索决策等价。

三种规模各做旧/新交错的三次单进程候选生成微基准；每次候选身份均完全相同：

## 6. 决策

1. 主要可安全优化的重复工作是 `_parent_alternatives()` 对未改变路线重复计算加工负载和全部有向相邻弧；本轮只改这一处。
2. 固定迭代搜索行为完全等价；默认开关关闭，因此历史生产行为不变。
3. 60 秒内迭代、有效候选和 B32 评价机会均显著增加；S1 一个 seed 和 I5 两个 seed 获得真实认证改善，另外九组持平，无回归。
4. 保留 `REGION + incremental LNS + HEURISTIC` 作为待独立验证的等价计算优化；本轮不额外运行 GAT，因为加速作用与排序器无关，且 HEURISTIC 已足以证明计算路径。
5. 该加速值得保留但不能包装成新的搜索算法贡献，也不能据 consumed-development 结果切换论文正式默认。若新的独立数据仍主要持平，应冻结算法并将剩余差距归因于搜索空间设计/强初值后的下降能力，而非继续微优化或重开 CRRR/GAT。
