# GNN+VNS 端到端计时与固定拆分专家数据审计

日期：2026-10-23  
运行环境：`D:\pybullet_test\.venv\Scripts\python.exe`，工作目录 `D:\pybullet_test\MRTA_GA`。

## 1. 结论

端到端计时已修正。新的完整求解模式从已读取实例开始计时，把模型加载、RULE/GNN 构造、初值修复与认证、方向 DP、B32、独立 certifier 和 VNS 放在同一个截止时间内。旧的固定认证初值模式仍保留，只用于研究 VNS，不能再标成完整算法时间。

修复后的 VNS 确实产生了更好的 TRAIN 教师：17/17 个实例得到并再次独立认证，17/17 都严格降低 Cmax；平均 Cmax 从 3251.247 s 降到 3116.590 s，按实例计算的平均改善为 4.58%，中位数为 2.42%。旧报告中的教师只有 16/17 可认证、3/16 严格改善，平均最终 Cmax 为 3269.262 s。由于旧集合少一个失败实例，该平均值不是严格配对统计；可直接比较的是认证覆盖率和严格改善覆盖率均明显提高。

但是，新的 `block -> robot` 知识仍然稀疏：980 个具有多个合法机器人选择的块中只有 17 个改变归属（1.73%），分布在 11/17 个实例；17 个变化全部是同轨左右机器人之间的变化，41 个具有跨轨选择能力的块中没有一个发生跨轨迁移。N1/N2/N3 分别贡献 9/7/72 次严格改善，说明当前收益很大一部分来自路线排序和同轨协调，而不是广泛的新任务归属。

因此本轮属于任务定义的 **情况 B**：教师显著降低了 Cmax，也包含少量有价值的同轨分工标签，但不足以证明立即重训一个只预测机器人归属的 GNN 会有实质收益。更合理的下一步是先让学习目标表达排序优先级或分配—排序耦合，再决定是否重训；不能用增加训练轮数或网络层数弥补标签信息不足。

两种模式的区别：

| 模式 | 起点 | 预算包含 | 用途 |
|---|---|---|---|
| 固定认证初值 VNS | 已经认证的同一初值 | 仅 VNS | 比较搜索策略 |
| 完整求解器 | 已读取 workbook 后开始 | 模型加载、构造、初值修复/认证、方向、B32、certifier、VNS | 比较 RULE+VNS 与 GNN+VNS |

workbook 读取仍按既有实验约定不计时。B32 是同步调用，不能保证函数恰好在截止时返回；因此同时报告 `overtime_seconds`。截止后完成的候选不会写入截止时最终 Cmax。

### 5.3 共同 X 排序诊断

RULE 归属 + X 排序有 16/17 可认证；专家归属 + X 排序有 14/17 可认证。两者都可认证的 14 个实例中，专家归属 + X 排序有 9 个 Cmax 更低，平均差为 -72.759 s。这给出了一部分“归属本身更好”的证据。

但有两个包含有效迁移的实例在专家归属恢复为 X 排序后发生 DEADLOCK，而其实际专家路线可以认证。这不是专家归属无效的证明，而是分配和同轨路线顺序强耦合的直接证据。因此该诊断不能被解释为严格因果分解。

## 7. 数据合法性与测试

保存后对 17 个 JSON 专家逐一执行了以下独立复核：

1. 从 workbook 重新加载父焊缝；
2. 从 JSON 重建固定拆分和四机器人有序路线；
3. 拆分模式逐项等于当前 `fixed_split_patterns()`；
4. 只含 WHOLE 和 mandatory Y_SPLIT，不含 X_SPLIT 或 optional split；
5. 每个实际焊接块恰好出现一次；
6. 每个 `block -> robot` 都通过 `robot_is_eligible()`；
7. 重新运行方向 DP、B32 和独立 certifier；
8. 17/17 再次认证，复算 Cmax 与 JSON 值绝对误差均小于 `1e-6`。

测试结果：

- `tests/test_gnn_construct_vns.py`：14 passed。
- GNN/VNS、WAG、HGA、geometry、certifier、interference 关键回归合集：107 passed in 9.06 s。

没有修改 GNN 网络、checkpoint、VNS 邻域、B32、certifier、正式问题定义或拆分域；没有增加 hash、协议、数据库、实验注册器或额外评分器。

## 8. 是否值得重新训练 GNN

本轮建立了可靠、可认证、明显优于旧短预算教师的专家数据，适合保留为后续研究资产。但对当前只预测 `block -> robot` 的 GNN，新增监督信息仍不足：98.27% 的多机器人可选块标签与 RULE 相同，所有变化都局限在同轨边界，跨轨共享区没有新正例，而 72 次 N3 改善不能被当前输出头学习。

明确判断：**现在不应仅用这批数据直接重训原样的归属 GNN并期待明显提高 GNN+VNS。** 下一轮应先验证一个能表达路线优先级、或显式联合分配与排序的简洁学习目标，并与 MLP 和 RULE 在相同端到端预算下比较。若仍坚持重训当前 GNN，应把它定位为小样本探索，并明确报告标签稀疏和多解等价风险；没有证据支持增加网络层、引入 PPO 或开放可选 Y/X 拆分。
