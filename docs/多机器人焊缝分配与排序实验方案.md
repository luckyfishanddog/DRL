## 1. 研究问题

研究对象为双滑轨四悬臂机器人焊接系统，工作区 `[0,20]×[0,12] m`，机器人顺序为 `R0=左上、R1=右上、R2=左下、R3=右下`。`y=6 m` 只作为上下滑轨名义交接中心，结合软交接带 `B_y=[6-δ_y,6+δ_y]` 使用，不作为越线即换机器人的硬所有权边界。本文研究任务层的焊缝线段分配、最多一次交接、排序、方向选择和理论干涉调度，不声称求解真实 IK、关节轨迹或三维机器人碰撞规划。

采用开放路线：不计 home 到第一条焊缝的部署时间，不要求回 home，但计相邻焊接块空走、焊前/焊后处理和理论干涉等待。计时起点的非空路线机器人必须已合法部署；第一项任务的起始配置满足同轨顺序和理论干涉约束。Formal F3 将 empty robot 明确视为未部署入二维任务域，不参加该检查；这是 TASK_HORIZON_RELEASE_V1 任务层假设，真实部署由下层控制负责。

主目标为

\[
\boxed{\min C_{\max}}
\]

重点回答：如何利用 By 完成 whole/Y-split assignment，并利用 Bx 作为同轨 spatial/load prior；如何避免免费拆分；如何联合 assignment、sequence、direction；如何用统一理论 scheduler 处理等待；以及如何显著减少昂贵协调评价，使 Python 实现的解质量—时间表现至少达到 HGA 与 WAG+VNS 同一量级。

## 2. 科学模型

### 2.1 基本运动与时间

主模型：

```text
welding speed      vw = 0.0108 m/s
empty-travel speed vm = 0.20 m/s
pre-processing     tpre = 20 s
post-processing    tpost = 30 s
```

`20/30 s` 采用 Lee 等文献正式实验设置作为 literature-based nominal values，不声称为当前设备实测值。

连续焊缝 `q`：

\[
T_q^{proc}=t_{pre}+\frac{L_q}{v_w}+t_{post}.
\]

相邻焊缝空走：

\[
T_{ij}^{move}=\frac{\|P_i^{end}-P_j^{start}\|_2}{v_m}.
\]

本实验统一采用：

```text
M0 = 2D Euclidean + constant speed
```

作为唯一运动时间模型。焊接与空走均在任务空间中按二维直线匀速运动计算，不再设置 `clearance plane`、梯形加减速或其他运动学敏感性模型。该简化与本文“焊缝任务分配、排序与理论干涉调度”的研究层级保持一致，也保证提出方法与 HGA、WAG+VNS 在相同运动时间模型下进行公平比较。M0 仅作为任务调度层的有效运动代价模型，不表示经过 IK、障碍物或真实三维机器人运动规划认证的轨迹。

### 2.2 拆分后的工艺时间

拆分本身不增加“切割时间”，但若父焊缝由两个机器人执行为两个独立 welding blocks，则两个 child 分别承担 `tpre + L/vw + tpost`。若虚拟片段最终仍由同一机器人连续执行，必须先 merge/canonicalize，再只计一次 pre/post。这样 optional split 具有并行收益，但不是免费收益。

### 2.3 正式目标

\[
C_r=T_r^{proc}+T_r^{move}+T_r^{wait},\qquad C_{\max}=\max_r C_r.
\]

正式解首先只比较 `Cmax`。仅当 `Cmax` 在数值容差内相等时，再依次比较：optional split 数、纯加工负载均衡、空走、等待。禁止用加权辅助指标换取更差的正式 `Cmax`。

## 3. 焊缝拆分

每个父焊缝最多拆分一次：

\[
\boxed{\text{one parent}\rightarrow 1\text{ or }2\text{ final welding blocks}}
\]

唯一最小子段阈值：

\[
\boxed{L_{min}=0.20m}.
\]

不增加比例阈值、人工 split penalty 或 restart penalty。

### 3.1 软交接带

主值：

\[
\delta_x=\delta_y=L_{min}=0.20m.
\]

该选择只表示 nominal handover tolerance，并不声称真实机器人工作空间重叠宽度就是 0.20 m。定义 `ηx=δx/Lmin, ηy=δy/Lmin`，主值均为 1，敏感性检查 `0.5/1.0/1.5/2.0`。所有 split 最终仍必须显式满足两个 child 均不短于 `Lmin`。

### 3.2 y 方向软边界

\[
B_y=[6-\delta_y,6+\delta_y]=[5.80,6.20]m.
\]

whole-seam 资格明确为：整条父焊缝均满足 `y>=6-δy` 时可由上轨整体执行；整条均满足 `y<=6+δy` 时可由下轨整体执行；若两者都满足，则上下轨均可作为 whole candidate；若两者都不满足，则必须在 `By` 内合法拆一次。

合法 y split 点 `P(t)=P0+t(P1-P0)` 必须满足 `P(t)∈By` 且 `tL>=Lmin,(1-t)L>=Lmin`。候选仅来自 `By` 下边界、中心、上边界交点和合法 midpoint，去重，不做毫米级网格枚举。

### 3.3 x 方向软边界

\[
B_x^{up}=[x_{up}-\delta_x,x_{up}+\delta_x],\qquad
B_x^{low}=[x_{low}-\delta_x,x_{low}+\delta_x].
\]

`x_up/x_low` 不是 hard ownership boundary。同轨两机器人原则上均保留 whole-seam candidate。

`x_up/x_low` 每个实例只按下节的加工时间加权 midpoint-x 中位数确定一次，然后冻结。`Bx` 在 development/formal 均仅用于 soft prior、spatial neighborhoods 与 features，不构成硬所有权边界。F1 已冻结 optional X_SPLIT=EXCLUDED：现有物理/工艺证据未给出独立必要性与完整有限候选规则；`XSplitValidator` 仅保留历史接口，不进入正式 domain。不从旧版本、Bx 边界或网格偷偷补候选，也不在 development 动态 shift。


#### 3.3.1 `x_up/x_low` 的确定性数学定义

为了避免“加权负载平衡”仍然存在实现歧义，主方法将 `x_up/x_low` 冻结为**加工时间加权 midpoint-x 中位数**。

对父焊缝 `i` 定义：

\[
x_i^c=\frac{x_i^{(0)}+x_i^{(1)}}{2},
\qquad
w_i=t_{pre}+\frac{L_i}{v_w}+t_{post}.
\]

对轨道 `g∈{up,low}`，令：

\[
\mathcal I_g
=
\{i:\text{父焊缝 }i\text{ 存在合法 whole-seam candidate 可由轨道 }g\text{ 执行}\}.
\]

定义总权重：

\[
W_g=\sum_{i\in\mathcal I_g}w_i.
\]

若 `W_g>0`，软交接中心定义为满足下式的**最左加权中位数**：

\[
x_g^*
=
\min
\left\{
x:
\sum_{\substack{i\in\mathcal I_g\\x_i^c\le x}}w_i
\ge
\frac{W_g}{2}
\right\}.
\]

然后进行工作区裁剪：

\[
x_g=\min(20-\delta_x,\max(\delta_x,x_g^*)).
\]

最终：

\[
\boxed{x_{up}=x_g\ (g=up),\qquad x_{low}=x_g\ (g=low)}
\]

经上述裁剪后在一个实例的整个求解过程中保持不变。

若某轨道 `\mathcal I_g=\varnothing`，则该轨道没有 whole-seam 任务，定义：

\[
x_g=10m
\]

作为纯确定性 fallback；该 fallback 不产生额外任务可行性。

同时，上下轨都 whole-eligible 的父焊缝可以同时进入 `\mathcal I_{up}` 与 `\mathcal I_{low}`，因为这里的 weighted median 只用于确定 soft handover prior，而不是做唯一任务分配。

该定义保证：

- 同一实例、同一参数下 `x_up/x_low` 唯一且可复现；
- `x_up/x_low` 不依赖任何算法运行结果；
- 不读取 VALIDATION/TEST 的最优解信息；
- GNN 的 `Bx` 静态特征在搜索过程中不会失效。

#### 3.3.2 正式辅助指标的数学定义

为避免“负载、空走、等待”等指标在实现中出现不同口径，统一定义：

对机器人 `r`，其最终 welding blocks 集合为 `Q_r`：

\[
P_r
=
\sum_{q\in Q_r}
\left(
t_{pre}+\frac{L_q}{v_w}+t_{post}
\right).
\]

纯加工负载不均衡：

\[
\boxed{
B_{proc}
=
\max_r P_r-\min_r P_r
}
\]

空走总时间：

\[
\boxed{
T_{empty}
=
\sum_r\sum_{(q_j,q_{j+1})\in route_r}
T^{move}_{j,j+1}
}
\]

总等待时间：

\[
\boxed{
W_{total}
=
\sum_r T_r^{wait}
}
\]

可选拆分数：

\[
\boxed{
N_{split}^{opt}
=
\sum_i
\mathbf 1
[
\text{parent }i\text{ 最终采用非 mandatory split}
]
}
\]

正式 `Cmax` 数值相等容差定义为：

\[
\epsilon_C
=
10^{-9}\max(1,|C_{\max}|)
\]

只用于浮点等价判断，不允许成为“牺牲一点 `Cmax` 换辅助指标”的工程容忍带。

正式词典序比较为：

\[
(C_{\max},
N_{split}^{opt},
B_{proc},
T_{empty},
W_{total},
\text{deterministic ID order}).
\]

cheap screening 可以使用这些量的局部近似增量，但任何近似量不得替代上述正式定义。

### 3.4 canonical solution

每个 parent 最终状态只能是：

```text
WHOLE
X_SPLIT(point)
Y_SPLIT(point)
```

三者在历史表示层互斥；development、历史 FORMAL_SCOPE_V1 与 active FORMAL_SCOPE_V1_1 均只允许 WHOLE/Y_SPLIT，X_SPLIT 保留历史接口且正式排除。若两个 child 最终回到同一机器人并连续执行，则 canonicalize 回 WHOLE；合并结果仍须通过 whole eligibility。任何 reference 评价前必须先 canonicalize，再计算 pre/post 和 `Cmax`。

## 4. 理论碰撞规避

采用 TCP-based planar interference abstraction，不等同于真实机器人本体三维碰撞。

### 4.1 operation 语义

```text
SETUP -> WELD -> POST -> MOVE -> SETUP -> WELD -> POST -> ...
```

`MOVE/WELD` 为线性运动；`SETUP/POST` 为端点静止；`WAIT` 定义为停留在上一 operation 终点。为避免旧方案中“只检查 MOVE/WELD，但又说 SETUP/POST 占位”的语义矛盾，主模型统一规定：

\[
\boxed{\text{MOVE, SETUP, WELD, POST, WAIT 均进入理论干涉检查}}
\]

WELD 与 MOVE 均不可中断；若未来执行会冲突，则整段 operation 延迟到 earliest safe start，不能执行到一半暂停。

### 4.2 连续时间二维判据

对时间重叠区间 `I`：

\[
\Delta x(t)=a_xt+b_x,\qquad \Delta y(t)=a_yt+b_y.
\]

若存在 `t∈I`：

\[
|\Delta x(t)|\le D_x+\epsilon_{num},\qquad |\Delta y(t)|\le D_y+\epsilon_{num},
\]

则判为理论干涉。主值：

\[
\boxed{D_x=D_y=0.50m}.
\]

敏感性检查 `(0.3,0.3)/(0.5,0.5)/(0.7,0.7)/(1.0,0.5)`。正式判定用连续时间解析区间，不用粗时间采样。

### 4.3 同轨不越位与初始状态

\[
x_{R0}(t)+D_x\le x_{R1}(t),\qquad x_{R2}(t)+D_x\le x_{R3}(t).
\]

该约束对 scope 内参与占位的机器人从计时起点成立。给定首方向后，第一项任务起点若破坏顺序或存在理论干涉，该 directed configuration 不合法；不能直接认定未定方向的 route combination 不可行，必须先检查第 5.2 节全部首方向组合。Formal F2/F3 采用 TASK_HORIZON_RELEASE_V1：final POST 的闭区间结束后与 empty route 均无 TCP/rail 占位；这与既有 development trajectory 一致，但正式声明为任务层假设。

### 4.4 reference scheduler

原方案只写 event-based earliest start，但没有冻结 dispatch priority，导致同一 route 可能因实现顺序不同得到不同 `Cmax`。主 scheduler 改成确定性 list scheduler：

1. 保持每台机器人 route precedence；
2. 对四台机器人 next operation 计算 earliest safe start；
3. 优先调度 earliest safe start 最小的 operation；
4. 并列时依次按 remaining processing load 更大、当前 completion 更大、robot ID 更小处理；
5. 固定该完整 operation 后重新计算其余 ready operations；
6. 直到全部完成。

没有有限 next-operation 选择时返回 DEADLOCK、wait-for graph 与 blocker diagnostics。Development 仍使用 DEVELOPMENT_NO_REPAIR_V1。Active formal F4 先运行同一 optimized policy；仅 DEADLOCK 时执行固定 32 complete-rollout 的 deterministic limited-discrepancy recovery；在完成的 FEASIBLE schedules 中按 Cmax、canonical schedule JSON 选唯一结果；耗尽仍为 DEADLOCK，不依赖 incumbent、算法或历史。Reference scheduler 是统一确定性协调启发式，不宣称全局调度最优。

Phase 2B-1.5 在不改变上述 priority、ESS 数学、WAIT、连续干涉或四状态语义的前提下完成性能闭合：保留 legacy slow scheduler 作为测试 oracle，production 使用 optimized scheduler。优化仅包括按 `end_time < ready - tolerance` 排除已过期 fixed operations、每机器人 remaining-processing suffix、以及 forbidden intervals 的一次确定性 sorted sweep；最终 candidate/WAIT conflict validation 仍保留。Slow/optimized 必须以 operation-level differential tests、DEADLOCK graph/diagnostics、随机小例和固定 evaluation-budget 搜索轨迹证明等价。若简单优化已通过 N=100、5 s 搜索门槛，不引入 incremental ESS。

所有 reference candidate、dataset 与统计统一使用以下四种 `schedule_status`：

| 状态 | 正式含义 | reference_cmax / SA / labels |
|---|---|---|
| FEASIBLE | 找到满足当前 scope 约束的 schedule；最终输出另经 independent certifier | 有有限 reference Cmax；允许 SA 与可行候选排序标签 |
| DEADLOCK | 当前 deterministic scheduler 未找到 schedule；可保留部分 timeline 和 wait-for graph | Cmax=null；不等于数学不可行，不进入 SA，不当 infeasible label |
| INFEASIBLE | 给定候选违反当前已定义约束，或有覆盖所声明范围的不可行性证明 | Cmax=null；不进入 SA；不能外推为整个 instance 不可行 |
| NUMERIC_FAILURE | 评价器异常、数值失败或结果无法可信评价 | Cmax=null；不进入 SA；隔离诊断，禁止作为劣质 candidate 正常训练 |

未调用 reference 的 C0–C3 候选只有 lifecycle/rejection reason，`schedule_status=null`，不是第五种 scheduler status。布尔 `feasible` 只能由 `status == FEASIBLE` 派生，不能用 feasible/infeasible 二分类覆盖四状态。Exact solver 自身的 OPTIMAL/LIMIT_REACHED 等是另一类 solver status，不能混进此字段；dispatch 穷举失败的证明边界见第 6.10.5 节。

### 4.5 independent certifier

certifier 从原始 parent pattern、assignment、route、direction、start/end times 独立检查：parent 覆盖、最多一次 split、child 长度、pre/post 次数、route precedence、non-preemptive、WAIT/SETUP/POST 占位、同轨顺序、连续时间二维干涉、最终 `Cmax` 重算一致。

增加 tiny scheduling oracle：2 台机器人、每台 2～4 个 operations，枚举少量 dispatch/conflict priority，报告 reference scheduler feasibility agreement 与 gap。

## 5. 三种方向语义

### 5.1 Exact micro：完整枚举

固定 canonical routes 后，对每个 welding block 完整枚举 forward=0 / reverse=1，共 `2^m` 个方向向量；每个向量独立 coordination。不能以 direction DP top-1 代替 exact direction enumeration。Phase 2A 已这样实现。

### 5.2 Ordinary search：Initial-Orientation-Constrained Direction DP

普通候选禁止枚举全部 `2^m`。Phase 1.1 的 `optimize_directions()` 仅实现自由首方向的 empty-travel DP，`DP1(0)=DP1(1)=0`，不能保证其 top-1 首方向合法。Phase 2B-1 已实现如下受约束封装：

1. Canonicalize 后按 R0…R3 顺序，给每条非空 route 枚举第一 block 的 0/1；最多 `2^4=16` 个首方向组合。Empty route 方向为 `()`，不引入 parking；全空 routes 只有一个空组合。
2. 用与 reference 相同的坐标和容差检查所有 active robots 的 initial theoretical interference，以及同轨 first-task order。只保留合法组合；必须同时考虑未被 move 修改的 route，不能只检查 affected routes。
3. 对合法组合中的 route 固定首方向 `b0`，初始化 `DP1(b0)=0, DP1(1-b0)=+∞`，递推

   `DP_i(b)=min_a [DP_(i-1)(a)+T_move(E_(i-1)(a),S_i(b))]`。

   每个状态按 `(empty_travel_time, 完整 orientation vector)` 升序取最优；不计 home/return-home，也不优化 WAIT。
4. 合法组合按 `(所有 route 的 T_empty 之和, 按 R0…R3 拼接的 orientation vectors)` 词典序取唯一结果。这里只使用方向阶段可知的指标；不能声称在 scheduler 之前按 Cmax 选方向。C4 后才使用完整正式 metric。
5. 若无合法首方向组合，记录 `NO_LEGAL_FIRST_ORIENTATION` 和拒绝原因，进入 reference evaluation failure path：若候选获 C4 名额，显式传入全 0 诊断方向向量（empty 为 `()`），用一次 reference 调用确认 INFEASIBLE；该调用计入 Kref/Nref。未获 C4 名额则保持未评价，不能伪造 scheduler status。禁止仅因自由 DP 的 deterministic tie-break 选错首方向就提前判失败。

每条 route 最多求两个固定首方向 DP，组合间复用结果；未改变 route 可复用其两个条件结果，但不能只缓存上轮全局 top-1。初始化调用一次该完整封装，C3 每候选调用一次；内部 route-DP 次数另计。将全部四条 route 的最终方向显式传给 `reference_schedule(..., orientations=...)`，禁止缺省回落到自由 DP。原始插入/交换筛选的 full DP calls=0、reference calls=0。

这种 DP 对给定首方向的空走目标精确，不能保证 reference Cmax 最优或后续无 DEADLOCK；它改变搜索选择，不改变 development feasible set。

### 5.3 Optional bounded schedule-aware direction refinement

后续 deterministic extension 可提供 `(canonical solution, explicit directions, FEASIBLE reference result, remaining budget) -> refined result + call counts` 接口。仅新 incumbent 或 high-wait case 允许触发少量 scheduler-aware flips，不能混入 C0–C3 或对每个普通候选触发。可从最多 2 条冲突 block、单 flip、每 trigger `Bdir<=4` 起步；启用前明确 high-wait 阈值、每实例硬上限和 tie，全部调用纳入 runtime/Nref，并受所属 iteration 的 Kref 剩余预算约束。只有 FEASIBLE 且正式 metric 改善才保留，最终 certifier 复核。

Phase 2B 第一版此项 inactive；它不是 F4 deadlock priority repair，也不补充 terminal/parking 规则。

## 6. 实验方法

### 6.1 方法选择：主创新不再是 GAT-PPO operator selection

原方案提出 `GAT/Graph Transformer + PPO + ALNS operator control`。审查后不建议把它作为论文核心创新，因为已有工作已经公开提出：GNN+DRL 用于 ALNS operator selection；DR-ALNS 用 DRL 选择 destroy/repair、调参数和控制接受准则；也已有 GCN/模仿学习学习 LNS destroy operator。

因此单纯把旧 MLP-PPO 换成 GAT-PPO，创新性不足，而且没有直接解决本项目最贵的 `reference scheduler`。

主方法改为：

> **GRC-ALNS：Graph-Ranked, Reference-Certified Adaptive Large Neighborhood Search**

核心：

\[
\boxed{\text{one-time graph encoding}+\text{candidate-level ranking}+\text{top-K reference evaluation}+\text{independent certification}}
\]

学习模块不决定最终 `Cmax`，只学习“当前哪些具体 candidate move 最值得送进昂贵 scheduler”。这与已有 operator-level RL 的学习粒度不同，并直接服务于本项目速度瓶颈。

### 6.2 确定性骨架 SA-OI-ALNS

保留不含学习的 SA-OI-ALNS 作为后续完整基线；Phase 2B 第一版只启用以下最小 move set：

```text
INTRA_RELOCATE
INTER_RELOCATE
SWAP
TWO_OPT
Y_SPLIT_ACTIVATE
Y_SPLIT_DEACTIVATE
Y_SPLIT_POINT_SWITCH
```

三个 Y move 对应现有 `MoveType.SPLIT_ACTIVATE/DEACTIVATE/POINT_SWITCH`，由候选生成器限制 pattern 为 Y_SPLIT；不需要为文档别名改现有枚举。Deactivate 仅允许 whole-eligible parent，不能去掉 mandatory Y；switch 仅选择现有合法 Y point，并重新检查 children eligibility。TWO_OPT 反转 route 子段后统一走第 5.2 节方向处理。

现有 CandidateMove 可表示 TWO_OPT_STAR，但第一版 inactive，列为第二批 deterministic extension。批量 destroy/repair、regret-2/3、多种 removal、bounded direction refinement、priority/deadlock repair、X moves 和动态 x_up/x_low shift 均不进入第一版 active backbone。启用新 extension 必须显式列出 active set 和评价预算，不能因数据结构支持就声称已实现。

固定输入、配置、algorithm seed 与 evaluation/iteration budget 时搜索应可复现；SA 允许使用 seeded RNG，“deterministic”不代表无随机数。Wall-clock 截止的 iteration 数可能因机器速度变化，另报告真实调用数。

#### 6.2.1 可复现 initial solution

1. **Patterns**：按 parent ID 升序；whole eligible 使用 WHOLE，optional Y 初始关闭。Mandatory Y 从 `generate_y_split_patterns()` 的合法结果中，过滤掉任一 child 无 eligible robot 的 pattern，按 `(t, point_id)` 升序取第一个；无合法 pattern 是当前 scope 的约束失败，不用 X 补救。
2. **Blocks**：展开上述 patterns，按 `(-[tpre+L/vw+tpost], parent_id, block_id)` 排序，依次插入。
3. **Bounded positions**：每个 block 枚举全部 eligible robots。长度为 n 的当前 route 有 `0..n` 个插入位置；development default `I_init=8`，若 `n+1<=I_init` 全取，否则取去重后的 `floor(j*n/(I_init-1)), j=0..I_init-1`，按位置升序。I_init 必须为不小于 2 的显式有界参数。
4. **Cheap insertion**：当前 route 保留 provisional orientation hints；邻居 hint 固定，仅为待插 block 比较 0/1，计算新增相邻 empty-travel 时间减去被替换相邻边时间。头/尾无 home 边，空 route delta=0；tie 取方向 0。按 `(P_r+T_proc(block), local_empty_delta, robot_id, position, hint)` 升序选插入，更新该 block hint 和 process load。禁止 raw insertion 调用 reference scheduler 或 full route DP；hint 不是最终方向。
5. **完整评价**：全部插入后 canonicalize；调用一次 Initial-Orientation-Constrained Direction DP，再显式传方向调用一次 reference scheduler。无合法首方向时按第 5.2 节诊断路径评价。只用 FEASIBLE 且 certified 的 initial 建立 current/best；其他状态不产生伪 Cmax。
6. **有限 fallback**：DEADLOCK 或已确认的首方向约束失败，只说明该次 construction 未成功，不将 instance 标为 INFEASIBLE。允许从空 routes 重新构造一次，保持 patterns、block 顺序和位置集合，唯一改为 `(projected_process_load, robot_id, local_empty_delta, position, hint)`。与第一次 canonical solution 重复则不重评。Development default `B_init=2`（包含首次，最多两个完整 construction、两次 reference 调用），找到首个 FEASIBLE 即停止；NUMERIC_FAILURE 隔离报错，不通过 fallback 掩盖。
7. 两次仍失败则运行结果记 `INITIALIZATION_FAILED`，保留每次真实 schedule_status/diagnostics；这是 run outcome，不是第五种 scheduler status，也不是 instance 数学不可行证明。不得隐藏扩大 B_init、改 patterns 或尝试 priority repair。

I_init/B_init 是 development defaults，不是论文冻结参数；其最终值只由 gate 之后的 VALIDATION 确定。初始化的 DP、reference、certifier 调用与耗时全部计入总预算，并与普通 iteration 统计分列。

### 6.3 接受准则

此前方案缺少 acceptance rule。所有 SA-OI-ALNS/GRC-ALNS 统一用 simulated annealing：改善解必接收；劣解按

\[
P_{acc}=\exp[-(C'_{max}-C_{max})/(T\,C_{scale})]
\]

接收。固定 normalization：

\[
C_{scale}=\max\left(1,\frac14\sum_{parent i}(t_{pre}+L_i/v_w+t_{post})\right).
\]

`Cscale` 不随 split pattern 改变，只作尺度归一化，不以此命名或替代 LB0。温度按 search 阶段实际 reference-evaluation count 衰减；四种返回状态的调用均计数，初始构造单独计数。T0、衰减率、Tmin 与 seed 必须为显式 development 配置，最终只由 VALIDATION 冻结，不在本轮替论文选择参数。

只有 C4 FEASIBLE candidate 有正式 Cmax。每 iteration 若多个候选 FEASIBLE，先按 `(Cmax, N_split_opt, B_proc, T_empty, W_total, deterministic ID)` 选唯一 proposal，再对它执行一次 SA；tie 使用第 3.3.2 节容差与现有 `OfficialMetrics.compare`，完全相同 metric 时按 CandidateKey 的规范字段顺序确定代表。Cmax 更优必接受；数值等价时接受，current 可以移动，但 best 只按正式 metric 更新；更差时用上述概率。无 FEASIBLE proposal 则 current 不变。T=0 仅接受非劣 Cmax，不进行除零。

DEADLOCK / INFEASIBLE / NUMERIC_FAILURE 均不进入 SA，分别统计。Rank/cheap score 不进入 acceptance probability，不用 penalty Cmax 代替失败状态。

### 6.4 有界 candidate pool

每次 ALNS iteration 只生成：

\[
|\mathcal C_t|\le M.
\]

`M=64, Kdp=8, Kref=2` 是 DEVELOPMENT DEFAULTS，须满足 `1<=Kref<=Kdp<=M`，不是论文冻结参数。最终值只能在 FORMAL_SCOPE_GATE 后由 VALIDATION 冻结，可考察 M=`32/64/128`、Kref=`1/2/4`。第一版以第 6.2 节 active moves 生成有界候选，稳定的 robot/block/position/point ID 与固定 seed 决定抽样和 tie；不先生成完整 O(N²) 邻域再截断。Spatial/critical/conflict neighborhood 可作 cheap proposal，批量 destroy 的 q 留给后续 extension。

M 约束筛选/去重前的 raw 生成尝试总数，cheap rejection 与 duplicate 都消耗该次数，不能无限补齐“64 个合法候选”。无合法候选时允许空 iteration，且仍受显式 iteration/wall-clock 停止预算约束。

### 6.5 静态图与动态解状态分离

原方案第二个重大 bug 是一方面写“GNN 只 forward 一次”，另一方面又把 current load、waiting 等动态量放入图节点。修正为：

静态 GAT 输入只含不会随搜索改变的焊缝几何、长度、方向角、base process time、固定 `Bx/By` 关系、whole eligibility、split candidate count、局部密度和静态 geometric conflict potential；robot token 只含 rail/left-right/ID。

GAT 每实例只运行一次，缓存 weld embedding `h_i`。

动态 route descriptor 单独计算，并且不能只做 set pooling，因为同一任务集合的不同排序必须被区分。每台机器人动态描述至少包括：节点 embedding pool、first/last embedding、当前相邻 directed transition embedding 聚合、process load、empty travel、waiting、completion、task count、split count、critical conflict count。只更新受 move 影响的 route。

### 6.6 candidate-level graph ranker

#### 6.6.1 candidate 的完整定义

一个 candidate 不是“某个算子名字”，也不是“尚未补全的 partial move”。

在 search state `S_t` 下，一个 candidate `c` 必须是一个**可以被确定性应用到当前 canonical solution 的原子解变换描述**：

\[
\boxed{
c=
(\tau,\mathcal Q_{src},\mathcal Q_{dst},
r_{src},r_{dst},
p_{src},p_{dst},
\pi_{split},
\pi_{dir}^{hint})
}
\]

其中：

- `τ`：move type；
- `Q_src/Q_dst`：涉及的 parent / welding-block IDs；
- `r_src/r_dst`：源/目标机器人；
- `p_src/p_dst`：删除与插入位置；
- `π_split`：formal scope 中 WHOLE/Y_SPLIT 的具体 pattern 与 split-point ID；X_SPLIT 仅保留在历史 development 表示中；
- `π_dir^hint`：只用于 cheap transition proxy 的方向提示，不是最终正式方向。

现有 CandidateMove 表示层支持以下类型；active/inactive 严格按第 6.2 节区分，development 的 split 仅允许 Y：

```text
INTRA_RELOCATE
INTER_RELOCATE
SWAP
TWO_OPT
TWO_OPT_STAR
SPLIT_ACTIVATE
SPLIT_DEACTIVATE
SPLIT_POINT_SWITCH
```

candidate 必须满足：

1. 从当前 `S_t` 出发应用一次即可得到唯一 provisional solution；
2. 不包含“repair 后再任意搜索若干步”这种不确定过程；
3. 所有 tie-break 唯一；
4. 相同 `S_t + candidate ID` 必须得到 bitwise-equivalent canonical solution（浮点容差除外）。

后续批量 destroy/repair extension 可产生较大的搜索扰动；ranker 只对具体、确定的原子候选排序。Phase 2B 第一版先完成最小 active moves，不把该 extension 算作已启用。

#### 6.6.2 candidate 生命周期

每个 candidate 依次经历：

```text
C0 raw
→ C1 cheap-feasible
→ C2 cheap-ranked
→ C3 exact-direction
→ C4 reference-evaluated
→ C5 accepted/rejected
```

- `C0→C1`：只检查 parent coverage、one split、Lmin、robot eligibility、route index、canonical duplicate cheap checks；先在 scope 内生成候选。Cheap reject 记录原因，不冒充 reference INFEASIBLE。
- `C1→C2`：仅使用 local travel delta、process-load delta、split delta、boundary relation、cheap conflict proxy。Phase 2B 使用明确记录的 deterministic cheap ordering；后续 ranker 也只读取这些 cheap/cached 特征（含已经存在的 state 描述与 static embedding）。禁止为了候选特征调用 reference scheduler 或 full route DP。
- `C2→C3`：最多 Kdp 个 shortlist 候选调用 Initial-Orientation-Constrained Direction DP；候选内最多 16 个首方向组合，第 5.2 节定义复用和 failure path。
- `C3→C4`：最多 Kref 个候选各调用一次 reference scheduler，显式传完整方向；返回 FEASIBLE / DEADLOCK / INFEASIBLE / NUMERIC_FAILURE。DP 失败获评价名额时也占一次调用预算，不能额外补无上限候选。
- `C4→C5`：只在 FEASIBLE 中按正式 metric 选 iteration proposal 后执行一次 SA；其他已评价候选分别记录未选为 proposal 或失败原因。

Phase 2B 第一版 cheap ordering 采用 `(projected_max_process_load, local_travel_delta, split_count_delta, CandidateKey)` 升序；主目标的 makespan proxy 优先于局部空走，不引入隐含 weighted penalty。C3 对 top Kdp 运行受约束方向 DP 后，按 `(projected_max_process_load, exact_directed_total_empty, split_count_delta, original_cheap_rank, CandidateKey)` 二次排序，再取最多 Kref；因此 Kdp 中非原 cheap top-Kref 的候选可以凭 exact direction 进入 reference shortlist。未来学习阶段替换排序策略时仍保持相同生命周期与硬预算。

Ordinary raw candidate 的 `full DP calls=0, reference calls=0`。每 iteration `Nref<=Kref`、`Kdp_count<=Kdp`，duplicate/cache hit 不冒充真实调用。只有 C4 FEASIBLE 具有正式 objective；未进入 C4 的候选保留未评价标记，不能把缺失目标值记为 0 或无限大训练标签。

#### 6.6.3 candidate identity 与去重

定义 candidate key：

```text
(
 current_solution_revision,
 move_type,
 sorted affected parent IDs,
 source/destination robot IDs,
 source/destination route positions,
 split-pattern ID / split-point ID
)
```

同一 iteration 中相同 key 只保留一次。需要排序时按上列字段顺序比较：move_type 用字符串 value，缺失 robot ID 用 -1、缺失 split ID 用空串，positions/IDs 保留 tuple；不依赖 set 遍历顺序或 Python 对 None/整数的比较。

若不同 move 描述 canonicalize 后得到完全相同 solution，则使用已有 canonical solution identity 去重；在同 scope/config 与第 5.2 节确定性方向规则下只评价一次。若复用 reference 结果，必须同时匹配实际方向向量及 evaluator policy；后续 direction refinement 的结果不能仅凭不含方向的 canonical hash 复用。无需新增 hash 机制。

每个 candidate 包含 move type、受影响任务 embedding、source/destination robot descriptor、局部 travel delta、load delta、split delta、soft-boundary relation、cheap conflict delta 和插入位置。

ranker 输出 `sθ(c|St)`。流程：

```text
bounded candidates
 -> cheap feasibility
 -> batched graph rank score
 -> top Kdp
 -> Initial-Orientation-Constrained Direction DP
 -> top Kref
 -> reference scheduler
 -> best FEASIBLE proposal by official metric
 -> SA acceptance
```

此处为 Phase 4/5 的 learned screening 接入点；Phase 2B 用 cheap ordering。`Kdp=8, Kref=2` 仍仅为 DEVELOPMENT DEFAULTS，参见第 6.4 节。


#### 6.6.4 ranker 与 SA 探索机制的解耦

若 ranker 永远只把最高分候选送入 reference scheduler，则 SA 虽然允许接受劣解，却实际上**看不到 ranker 判为低分但具有长期探索价值的候选**，会造成 exploitation bias。

因此明确：

\[
\boxed{\text{ranker 只控制 evaluation budget，不控制 SA acceptance}}
\]

Phase 4/5 的 learned reference shortlist 保留强制探索配额；本节不是 Phase 2B 第一版 active policy。

当 development trial 使用以下预算时：

\[
K_{ref}=2.
\]

学习阶段 ordinary iteration：

```text
1 个 exploit candidate：
    受约束方向 DP 后 rank score 最高

1 个 exploration candidate：
    从剩余 Kdp-1 candidates 中按 exploration policy 选择
```

探索候选不允许再次选择 rank top-1。

主 exploration policy 使用：

\[
P(c)
\propto
\exp
\left(
\frac{\tilde s_\theta(c)}{\tau_{rank}}
\right)
+
\lambda_{nov}\,Novelty(c)
\]

其中 `Novelty(c)` 根据最近 `H` 次 accepted/evaluated move 的：

- move type；
- affected parent；
- source/destination robot；

计算。

学习阶段首版可以简化为：

```text
50%：从非 top-1 的 Kdp shortlist 中按 softmax(score) 采样
50%：从非 top-1 shortlist 中均匀采样
```

随机数由 algorithm seed 固定。

当 search 连续 `S_stag` 次 reference evaluations 未改善 best solution 时，进入短暂 diversification：

```text
exploration candidate 优先选择 novelty 最大者
```

`S_stag` 只在 VALIDATION 冻结。

SA acceptance 始终在 reference `Cmax` 得到之后执行：

- exploit candidate 可能被接受或拒绝；
- exploration candidate 同样可能被接受或拒绝；
- 两个 candidate 都 reference-evaluated 后，仅在 FEASIBLE 子集中按正式词典序确定本 iteration 的 proposal，再执行 SA acceptance；无 FEASIBLE 则不提议移动；
- 不允许 rank score 直接进入 acceptance probability。

这使：

> ranker 负责“值得花 evaluator 预算看谁”，SA 负责“已经看过以后是否接受”。

#### 6.6.5 防止 ranker feedback loop 的训练采样

offline ranker 数据不能只来自“旧 ranker 已经挑中的候选”，否则会形成自我强化的 selection bias。

TRAIN 数据至少包含：

```text
40% heuristic-top candidates
30% uniform-random candidates
20% novelty/diversification candidates
10% near-tie/hard-negative candidates
```

比例可以在 VALIDATION 小幅调整，但必须保证存在固定的 ranker-independent exploration data。

正式测试中 ranker 不更新。

### 6.7 训练改为 learning-to-rank

主训练不再用在线 PPO。FORMAL_SCOPE_GATE 后，只在 TRAIN 上收集 FEASIBLE SA-OI-ALNS search states；对每个 state 采少量 candidates，离线 reference evaluation 分别记录四种 schedule_status。只有 candidate 与 state 均 FEASIBLE 时才得到 `delta_cmax_if_feasible = candidate.reference_cmax - state.reference_cmax`，用于 pairwise/listwise ranking 或 regression。可选 status 辅助头必须区分 DEADLOCK 与 INFEASIBLE；NUMERIC_FAILURE 隔离，不作为正常负例。禁止用 feasible/infeasible 二分类取代原始 scheduler status。

训练数据从约 `1e4` labelled candidates 起步，只在 VALIDATION 未饱和时扩展，并设置硬上限，禁止生成全空间 catalog。

旧 MLP-PPO 与 GAT-PPO operator controller 只保留为内部学习基线，不再作为主方法。

### 6.8 正式速度契约

正式测试计时包括：problem-specific preprocessing、split candidate construction、一次 GAT forward、initial solution、search、reference scheduling、final certification。只排除 Python process startup、权重从磁盘加载和 offline training。

主 runtime benchmark 用 CPU 单进程固定线程；训练可用 GPU。固定时间：`1 s / 5 s / 30 s`，5 s 为 primary。必须报告 time-to-target、Nref、candidate count、GNN/ranker/scheduler 时间。

禁止隐藏：全 `x_up/x_low` cell、全 split grid、每 raw insertion full DP、每 raw insertion reference scheduler。

### 6.9 Phase 2B 性能与 gap 统计

每次运行记录 scope_id、scientific config、seed、active move set、M/Kdp/Kref、I_init/B_init、SA 参数与真实 wall-clock；开发日志不能冒充 formal experiment。至少包含：

```text
iterations
raw_candidates
cheap_feasible_candidates
Kdp_count
Nref
N_feasible / N_deadlock / N_infeasible / N_numeric_failure
candidate_generation_time
cheap_screen_time
direction_dp_time
reference_scheduler_time
certifier_time
scheduler_mean / scheduler_p50 / scheduler_p95
init_scheduler_mean / init_scheduler_p50 / init_scheduler_p95
search_scheduler_mean / search_scheduler_p50 / search_scheduler_p95
requested_budget / actual_runtime / overshoot
last_reference_start / last_reference_end
best_Cmax_at_1s / best_Cmax_at_5s / best_Cmax_at_30s
```

Kdp_count 是进入 C3 的候选数，内部条件 route-DP calls 另计；Nref 是 search-stage 实际调用数，不是候选数，初始化调用另记 `init_reference_calls`。四个 search-stage reference status counts 的和等于 Nref；cheap rejection 和 cache hit 不计入这些状态计数。Scheduler duration 必须分别保留 initialization、search 与 all 三组 mean/p50/p95，零调用记 null。Wall-clock scheduler 不在线程中强杀，只在安全边界检查；因此同时记录请求预算、真实 runtime、overshoot 与最后一次 reference 的 start/end。计时分段不能从总预算扣掉初始化、失败候选或 final certifier；学习阶段另加 GNN/ranker 时间。

Anytime 只记录截止时间前已经完成评价的 best FEASIBLE Cmax；没有解记 null 与原因，不填 0。最终返回解必须完成 certification，certifier 时间计入预算；跨过截止时间才完成的结果不得回填早期 checkpoint。Micro cases 额外记录同一 scope/config 的：

```text
C*    = Cmax_OPT_Y_CURRENT
Cref  = ALNS reference Cmax
Ccoord = ALNS exact-coordination Cmax
search_gap    = Ccoord - C*
scheduler_gap = Cref - Ccoord
```

Ccoord 固定 ALNS 输出的 pattern、assignment、route 和 directions，只重新优化 coordination；不可重新枚举方向而把方向损失算进 scheduler_gap。Search_gap 包含 pattern/assignment/route/direction 的搜索损失。总差 `Cref-C* = search_gap+scheduler_gap`，可另报告二者各除以 C* 的百分比（C*=0 时百分比 null）。必须先完成相同范围的 exact enumeration；LIMIT_REACHED、NUMERIC_FAILURE 或缺失 FEASIBLE 值时 gap=null 并解释。Development 的 C* 与 gap 仅在当前 dispatch+ESS 枚举域下解释，连续时间全局性受第 6.10.5 节限制；不能把负 gap 静默截为 0，应诊断模型/实现/声明问题。上述 exact 重调度是计时之外的 micro 诊断，不参与 ALNS acceptance。

### 6.10 Exact micro 与 lower-bound 的范围

Tiny scheduler oracle 验证固定 route/direction 的 coordination；micro solver 还枚举 pattern、assignment、route 与 directions。必须区分以下两个层次。

#### 6.10.1 Development exact 与 final formal exact

**Development exact（Phase 2A 已实现）**：

```text
scope = EXACT_Y_SCOPE_CURRENT_SEMANTICS
whole eligible: WHOLE + all current legal Y_SPLIT
otherwise: mandatory Y_SPLIT only
X_SPLIT excluded
robot assignment
route permutation
every block forward/reverse direction
independent dispatch interleaving + earliest-safe-start coordination
independent certification
reported objective = Cmax_OPT_Y_CURRENT
```

当前默认 `max_parents=4`；更大规模须显式 `allow_larger=True`，不能写作已经完成 N<=6 full-scope exact。Exhaustive 模式除 canonical duplicate suppression 外不剪枝；B&B 使用现有 processing/remaining-duration 安全下界与等值 WAIT 条件。Route heuristic、reference priority、direction top-1、未经证明的 symmetry/dominance 不能删 exact 分支。Time/state/evaluation limit 命中必须返回 LIMIT_REACHED、optimal=False，不能填写 Cmax_OPT_Y_CURRENT 或 optimality gap。

Phase 2A 的实现级 OPTIMAL / Cmax_OPT_Y_CURRENT 表示已穷尽当前离散空间与 dispatch+ESS generator；不是未经证明的连续时间全局 exact 声明。Independent certifier 证明返回 schedule 合法，不证明 generator 覆盖所有连续时间最优 schedule。

**Final formal exact（未实现）**：只有 active `FORMAL_SCOPE_V1_1` 冻结，exact 的 patterns（WHOLE/Y_SPLIT，X 已排除）、eligibility、occupancy、initial rules、时间和冲突语义与正式方法使用完全相同 final feasible set，且通过 `EXACT_SCHEDULER_VALIDITY_GATE` 后，才允许使用 `Cmax_OPT`。Reference recovery 是评价策略，不能把 exact 限制为仅搜索该 priority；两者必须共享物理约束与可行域。

正式报告同时标明 scope、完成枚举的范围和 exactness 证据类型；B 路径仅允许受验证范围限定的称谓，不能把无反例写成全局证明。`Cmax_OPT_Y_CURRENT` 与 `Cmax_OPT` 不得混写、混表或用同一个无范围 OPT 字段代替。

#### 6.10.2 Analytical lower bound — LB0 已完成

对中大实例定义一个不依赖算法的基础下界。

每个父焊缝至少需要一次 pre/post，并完成全部焊接长度，因此总 processing work 至少为：

\[
W_0
=
\sum_i
\left(
t_{pre}+\frac{L_i}{v_w}+t_{post}
\right).
\]

所以：

\[
LB_{work}
=
\frac{W_0}{4}.
\]

由于每个 parent 最多只能形成两个并行 blocks，因此任意父焊缝 `i` 的完成跨度不可能小于：

\[
LB_i^{parent}
=
t_{pre}+t_{post}+\frac{L_i}{2v_w}.
\]

于是：

\[
LB_0
=
\max
\left(
LB_{work},
\max_i LB_i^{parent}
\right).
\]

该下界忽略：

- empty travel；
- interference waiting；
- robot eligibility；
- split-point restriction；

在当前 one-parent 最多两个 blocks 的模型下不会高估 optimum，但可能较松；空 parent 集合 LB0=0。`mrta_exact/lower_bounds.py` 已实现并验证。Formal scope 冻结后仍需检查其假设是否保留，不能自动沿用失效的下界。

#### 6.10.3 Eligibility-aware LP lower bound — LB_LP 尚未实现

Phase 2B0 不实现 LP solver。Deterministic backbone 稳定、FORMAL_SCOPE_V1_1 冻结之后，在 Phase 6、正式最终测试之前建立 assignment relaxation：

- 忽略 route order、empty travel 和 interference；
- 保留 upper/lower/robot eligibility；
- 保留 FORMAL_SCOPE_V1_1 的合法 WHOLE/Y_SPLIT；F1 明确排除 X_SPLIT；
- 将 pattern/assignment binary variables 放松到 `[0,1]`；
- 最小化最大机器人 process load。

其最优值记为：

\[
LB_{LP}.
\]

正式中大实例下界：

\[
\boxed{
LB
=
\max(LB_0,LB_{LP})
}
\]

报告：

\[
Gap_{LB}
=
\frac{C_{\max}^{method}-LB}{LB}\times100\%.
\]

`LB` 只用于质量解释，不参与算法 reward、ranker label 或参数选择。

#### 6.10.4 exact / lower-bound 验证的作用

最终论文至少同时给出：

1. 通过 scope/validity 条件后，micro instances 的有明确范围的 exact gap，并分解 search_gap / scheduler_gap；
2. normal instances 的 lower-bound gap；
3. reference scheduler 对 tiny scheduling oracle 的 scheduler-only gap。

这样可以把三个不同问题分开：

```text
搜索器离全局最优有多远？
scheduler 本身损失多少？
大实例虽然未知最优，但离有效下界有多远？
```

#### 6.10.5 EXACT_SCHEDULER_VALIDITY_GATE

当前 exact scheduler 枚举 dispatch interleaving，并对每个 next operation 做 earliest-safe-start placement。已有 brute/B&B、独立 tiny oracle 和 certifier 测试是重要证据，但 tiny oracle 仍使用同类 dispatch+ESS 思路；这些测试不自动证明连续时间全局 exact。

在论文最终使用 Cmax_OPT 前，至少完成以下一种路径，并在 Phase 6 留下适用范围与结论：

- **A：理论论证**。证明本模型存在最优 schedule 可由当前 serial schedule generation + ESS 产生，给出 left-shift / active-schedule dominance 论证。必须覆盖 WAIT 占位、同轨不越位、MOVE/WELD 不可中断、初始状态、最终冻结的 terminal/empty 语义，以及闭区间碰撞和数值边界（必要时区分 attained minimum 与 infimum）。
- **B：不同机制验证**。在极小 N 建立 independent continuous-time oracle / counterexample search；不能只是再写一个 dispatch+ESS，也不能用粗 dt 网格替代连续时间。记录实例范围、搜索机制、终止条件与误差控制，与当前 generator 比较且未发现违反 exactness 的情况；论文明确这是受限验证、没有一般性证明，只在被验证范围内使用有此限定的 Cmax_OPT。若发现反例，则修正 generator 或缩小 exact 声明范围后重验。

本门只控制正式论文 exact 声明，不阻止 Phase 2B development。Code 中 exact/tiny oracle 的 INFEASIBLE 若仅因所有 dispatch+ESS 分支失败，当前只能读作“该 generator 枚举域无解”；没有 A 或独立不可行性证据时，不得升级成连续时间数学不可行证明。原始 API status 保留并注明来源，不能拿它替 reference 的四状态标签。E3 已证实 reference DEADLOCK 可有可行 schedule；E4 的分支失败也不是一般性证明。

2026-09-29 intake 实测得到 96 个 frozen family workbooks、2942 个 valid unique platform sheets，manifest hash `3a12fc59708fcd6adc20bb19ba44ba8ece585f8e0a81a93304694960f18f2a31`。其中 2893 个（98.3345%）满足当前主实验范围 `10 <= N <= 90`；49 个 N>90 实例仍为 manifest-valid，只归为 large-scale stress/out-of-main-range，不参与本轮主范围 gate。

Phase 3-0.5 对历史 N=55 失败逐级诊断：四种既有 construction 与每种前四个合法方向均保持 DEADLOCK；该实例没有可选合法 Y-split，pattern portfolio 无法产生新状态。诊断表明终态阻塞集中在同轨机器人对。生产修复只增加一次有界、确定性的 `RAIL_SERIAL_BOOTSTRAP`：正常 portfolio 失败后，每轨仅启用一台机器人，flexible block 按 rail load 确定分配并按 X 单调排序；焊缝、split domain、reference evaluator、certifier、`FORMAL_SCOPE_V1_1` 与 B32 均不变。

`PPO_INIT_BOOTSTRAP_DEVSET_V1` 按 N=10–30、31–50、51–70、71–90 四层各取 5 个，按 geometry hash 稳定选择并在可行时每个 workbook 最多一个；20/20 初始化 SUCCESS 且 certified，NUMERIC_FAILURE=0。`PPO_PHASE3_SMOKESET_V2` 以 solver-independent min/median/max 规则选择 N=10/55/90：5 s 三者均进入 search（iterations=19/3/1）且 final certified；N=55/N=90 的 30 s iterations=17/7 且 final certified。V1 的 N=102 历史 smoke 保留；一次 out-of-range 初始化 replay 也 certified，但不作为主范围 gate。

由此 `PPO_DATA_INTAKE_STATUS=PASS`、`PPO_ALNS_INITIALIZATION_STATUS=PASS`、`PHASE3_1_AUTHORIZED=YES`。未来正式 split 必须按完整 workbook/generation-seed family 隔离；bootstrap devset 与历史 smoke 消耗过的 workbook 全部排除在 untouched TEST 之外。本轮未定义 TRAIN/VALIDATION/TEST/OOD split，也未依据 solver outcome 选择实例。

### 8.6 Phase 3 — Adapted HGA / WAG common-model

Phase 3-0 intake PASS 后，先完成 paper-aligned sanity，再按 FORMAL_SCOPE_V1_1 接入共同模型，保留各自 route/direction/search。所有方法读取同一 `PPO_DATASET_MANIFEST_V1` frozen instance，不允许运行时生成几何。用 gate 后另行冻结的 VALIDATION 调参，禁止读 TEST。若 SA-OI-ALNS 的 5s 性能明显落后，先修 backbone，再进入学习阶段；调整搜索不能改变已冻结可行域。

Phase 3-1 已完成：`PPO_PHASE3_DATA_SPLIT_V1` 以 whole workbook/seed family 为单位、仅用 solver-independent 几何描述符冻结角色，split hash 为 `5b5e3a6d43b943c5bad03a9ecbadaefa74c6158b33036da6e0fc236e03af1c5a`。`ADAPTED_HGA_V1` 保留论文 population、route crossover、M1--M6 VND 与 objective+route-edge-diversity survival；`ADAPTED_WAG_VNS_V1` 保留 multiple WAG、nearest/farthest、2-opt、factorial combination、route combinations 与 MOVE/SWAP/LNS。两者支持合法 optional/mandatory Y，最终完整候选统一使用 shared direction DP、`FORMAL_SCOPE_V1_1` evaluator、certifier 和 official metrics。首轮 development smoke 仅使用 DEVELOPMENT_CONSUMED，ID_TEST 没有进入任何 solver/evaluator/certifier。

### 8.7 Phase 4 — Ranker data + MLP ranker

只在 FORMAL_SCOPE_V1_1 的 TRAIN 轨迹上采 representative FEASIBLE states，生成 bounded candidates，离线标注小批候选。约 1e4 个 labelled candidates 是开发起点，扩展有硬上限；不生成全空间 catalog。混合 heuristic-top、uniform-random、novelty/diversification、near-tie hard negatives，来源比例见第 6.6.5 节，不只标注旧 ranker 选中的候选。

未来 ranker dataset schema 至少包含：

```text
scope_id / scope identity / scientific_config_hash / reference_policy_id
repository_id / source_commit / source_tree_hash / worktree_dirty / commit_verified
state_id / state_reference_cmax
candidate_key / candidate_features / move_type
lifecycle_stage / exploration_source
schedule_status
reference_cmax
delta_cmax_if_feasible
diagnostics / evaluator_version
```

FEASIBLE 时 reference_cmax 为有限数，delta_cmax_if_feasible 为相对 FEASIBLE state 的真实差值。DEADLOCK / INFEASIBLE / NUMERIC_FAILURE 分开保留，后两字段均 null；保留 wait-for/constraint/numeric diagnostics。未评价候选 schedule_status=null，按 lifecycle 标记未标注；null 不是 scheduler status。严禁 DEADLOCK→infeasible label、失败候选 penalty Cmax、NUMERIC_FAILURE 正常负例，或把缺失值填零。Pairwise/listwise Cmax 训练只使用可比较的 FEASIBLE labels；可选状态预测头保留状态区别并隔离数值失败。

先验证 MLP learned screening 是否保持质量并降低 Nref；label 与现有 state/candidate 编码之间需可追溯。Development 数据不能直接作为最终训练 labels，scope 变更后重评。

### 8.8 Phase 5 — Graph ranker / GRC-ALNS

实现 static graph、one-time GAT、dynamic route transition pooling、candidate batch scorer、top-K shortlist。相同任务集合不同 route 顺序必须产生不同动态描述，GAT 每实例只 forward 一次。可选 GAT-PPO operator-control 仅作附录基线，不改变主阶段顺序。正式测试不更新 ranker。

性能审计包括 preprocessing、initialization、generation、cheap screen/ranking、DP、scheduler、certifier；不得有旧 4N、全 cell/split grid、raw full DP、无界 N² 邻域或隐藏 scheduler 调用。CPU/thread、计时边界与 HGA/WAG 相同。

### 8.9 Phase 6 — LB_LP + final exact validation

在 backbone 稳定和 FORMAL_SCOPE_V1_1 冻结后完成 LB_LP、同一 final feasible set 的 exact micro，并通过 EXACT_SCHEDULER_VALIDITY_GATE。用更小 brute force/不同机制证据检查 exact 的适用范围、limits 和 infeasibility 声明；不能以 shared-generator 测试替代证明。

检查 `LB0 <= 同 scope 的已证实 optimum`、`LB_LP <= 同 scope 的已证实 optimum`，以及所有 certified 方法解 `Cmax>=LB`；若只有 B 路径证据，明确所比较值的验证范围。下界高于任何 certified feasible Cmax 已是反例，立即修正后才做最终测试。Micro 报告 search_gap 与 scheduler_gap，不只给一个混合 gap。

### 8.10 Phase 7 — Frozen VALIDATION / ID_TEST / OOD experiments

论文正式数据从 `PPO_DATASET_MANIFEST_V1` 的 valid unique frozen platform instances 中按预声明、solver-independent 规则另行划分 TRAIN、VALIDATION、ID_TEST；只有真实数据统计支持时才定义 OOD_SIZE/OOD_GEOMETRY，不硬造伪 OOD。源目录的历史 role 名不自动成为本研究 split。FORMAL_SCOPE_GATE 后的 VALIDATION 只用于 M/Kdp/Kref、initial/search 参数、GAT size、rank loss 等选择，不可调换科学可行域；本阶段开始前参数与统计协议冻结，然后一次性运行 ID_TEST/OOD。VALIDATION 的调参轨迹与最终报告保留，但 TEST 不能反馈训练或调参。

执行第 7 节比较、消融、多 seeds 和统一 wall-clock；论文 Cmax_OPT 只有第 6.10 节条件满足才使用。正式方法 Cmax 始终来自统一 reference evaluator 并经独立 certifier，最优值诊断来自注明范围的 exact solver，两者不混为同一种输出。

### 8.11 论文结果解释

若 GRC-ALNS 优于 SA-OI-ALNS 且后者优于 HGA/WAG，并显著减少 Nref、不拖慢 time-to-target，主贡献为 graph-ranked reference-certified search。若 GRC-ALNS≈SA-OI-ALNS，学习模块作为附加实验；若 backbone 明显落后，则继续优化搜索并重新验证，不通过改变可行域制造优势。

最终科学定位保持 soft one-time handover、orientation-integrated routing、continuous theoretical scheduling 与 graph-ranked screening。神经网络只影响候选评价顺序，不替代最终 scheduler/certifier。
