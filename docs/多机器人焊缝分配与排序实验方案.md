# 多机器人焊缝分配与排序 实验方案（审查优化版）

## 1. 研究问题

研究对象为双滑轨四悬臂机器人焊接系统，工作区 `[0,20]×[0,12] m`，机器人顺序为 `R0=左上、R1=右上、R2=左下、R3=右下`。`y=6 m` 只作为上下滑轨名义交接中心，结合软交接带 `B_y=[6-δ_y,6+δ_y]` 使用，不作为越线即换机器人的硬所有权边界。本文研究任务层的焊缝线段分配、最多一次交接、排序、方向选择和理论干涉调度，不声称求解真实 IK、关节轨迹或三维机器人碰撞规划。

采用开放路线：不计 home 到第一条焊缝的部署时间，不要求回 home，但计相邻焊接块空走、焊前/焊后处理和理论干涉等待。为避免“免费部署”绕过同轨不越位，计时起点定义为四台机器人已完成合法初始部署；第一项任务的起始配置也必须满足同轨顺序和安全间距。

主目标为

\[
\boxed{\min C_{\max}}
\]

重点回答：如何利用 `Bx/By` 软交接完成 whole/split assignment；如何避免免费拆分；如何联合 assignment、sequence、direction；如何用统一理论 scheduler 处理等待；以及如何显著减少昂贵协调评价，使 Python 实现的解质量—时间表现至少达到 HGA 与 WAG+VNS 同一量级。

## 2. 科学模型

### 2.1 基本运动与时间

主模型：

```text
welding speed      vw = 0.0108 m/s
empty-travel speed vm = 0.20 m/s
pre-processing     tpre = 20 s
post-processing    tpost = 30 s
```

`20/30 s` 采用 Lee 等文献正式实验设置作为 literature-based nominal values，不声称为当前设备实测值。

连续焊缝 `q`：

\[
T_q^{proc}=t_{pre}+\frac{L_q}{v_w}+t_{post}.
\]

相邻焊缝空走：

\[
T_{ij}^{move}=\frac{\|P_i^{end}-P_j^{start}\|_2}{v_m}.
\]

本实验统一采用：

```text
M0 = 2D Euclidean + constant speed
```

作为唯一运动时间模型。焊接与空走均在任务空间中按二维直线匀速运动计算，不再设置 `clearance plane`、梯形加减速或其他运动学敏感性模型。该简化与本文“焊缝任务分配、排序与理论干涉调度”的研究层级保持一致，也保证提出方法与 HGA、WAG+VNS 在相同运动时间模型下进行公平比较。M0 仅作为任务调度层的有效运动代价模型，不表示经过 IK、障碍物或真实三维机器人运动规划认证的轨迹。

### 2.2 拆分后的工艺时间

拆分本身不增加“切割时间”，但若父焊缝由两个机器人执行为两个独立 welding blocks，则两个 child 分别承担 `tpre + L/vw + tpost`。若虚拟片段最终仍由同一机器人连续执行，必须先 merge/canonicalize，再只计一次 pre/post。这样 optional split 具有并行收益，但不是免费收益。

### 2.3 正式目标

\[
C_r=T_r^{proc}+T_r^{move}+T_r^{wait},\qquad C_{\max}=\max_r C_r.
\]

正式解首先只比较 `Cmax`。仅当 `Cmax` 在数值容差内相等时，再依次比较：optional split 数、纯加工负载均衡、空走、等待。禁止用加权辅助指标换取更差的正式 `Cmax`。

## 3. 焊缝拆分

每个父焊缝最多拆分一次：

\[
\boxed{\text{one parent}\rightarrow 1\text{ or }2\text{ final welding blocks}}
\]

唯一最小子段阈值：

\[
\boxed{L_{min}=0.20m}.
\]

不增加比例阈值、人工 split penalty 或 restart penalty。

### 3.1 软交接带

主值：

\[
\delta_x=\delta_y=L_{min}=0.20m.
\]

该选择只表示 nominal handover tolerance，并不声称真实机器人工作空间重叠宽度就是 0.20 m。定义 `ηx=δx/Lmin, ηy=δy/Lmin`，主值均为 1，敏感性检查 `0.5/1.0/1.5/2.0`。所有 split 最终仍必须显式满足两个 child 均不短于 `Lmin`。

### 3.2 y 方向软边界

\[
B_y=[6-\delta_y,6+\delta_y]=[5.80,6.20]m.
\]

whole-seam 资格明确为：整条父焊缝均满足 `y>=6-δy` 时可由上轨整体执行；整条均满足 `y<=6+δy` 时可由下轨整体执行；若两者都满足，则上下轨均可作为 whole candidate；若两者都不满足，则必须在 `By` 内合法拆一次。

合法 y split 点 `P(t)=P0+t(P1-P0)` 必须满足 `P(t)∈By` 且 `tL>=Lmin,(1-t)L>=Lmin`。候选仅来自 `By` 下边界、中心、上边界交点和合法 midpoint，去重，不做毫米级网格枚举。

### 3.3 x 方向软边界

\[
B_x^{up}=[x_{up}-\delta_x,x_{up}+\delta_x],\qquad
B_x^{low}=[x_{low}-\delta_x,x_{low}+\delta_x].
\]

`x_up/x_low` 不是 hard ownership boundary。同轨两机器人原则上均保留 whole-seam candidate。

当前方案原本同时写了“`x_up/x_low` 可在搜索中 shift”和“GNN 静态图只编码一次”，二者冲突。主方法改为：`x_up/x_low` 每个实例只确定一次，然后冻结。建议按上/下轨分别用父焊缝 midpoint-x 和基础加工时间 `tpre+L/vw+tpost` 做长度/工时加权负载平衡，得到确定性 nominal handover center。`Bx` 只用于 soft prior、optional x split 候选和 spatial neighborhoods。动态 shift 仅作为附录消融，不进入主算法。


#### 3.3.1 `x_up/x_low` 的确定性数学定义

为了避免“加权负载平衡”仍然存在实现歧义，主方法将 `x_up/x_low` 冻结为**加工时间加权 midpoint-x 中位数**。

对父焊缝 `i` 定义：

\[
x_i^c=\frac{x_i^{(0)}+x_i^{(1)}}{2},
\qquad
w_i=t_{pre}+\frac{L_i}{v_w}+t_{post}.
\]

对轨道 `g∈{up,low}`，令：

\[
\mathcal I_g
=
\{i:\text{父焊缝 }i\text{ 存在合法 whole-seam candidate 可由轨道 }g\text{ 执行}\}.
\]

定义总权重：

\[
W_g=\sum_{i\in\mathcal I_g}w_i.
\]

若 `W_g>0`，软交接中心定义为满足下式的**最左加权中位数**：

\[
x_g^*
=
\min
\left\{
x:
\sum_{\substack{i\in\mathcal I_g\\x_i^c\le x}}w_i
\ge
\frac{W_g}{2}
\right\}.
\]

然后进行工作区裁剪：

\[
x_g=\min(20-\delta_x,\max(\delta_x,x_g^*)).
\]

最终：

\[
\boxed{x_{up}=x_{up}^*,\qquad x_{low}=x_{low}^*}
\]

经上述裁剪后在一个实例的整个求解过程中保持不变。

若某轨道 `\mathcal I_g=\varnothing`，则该轨道没有 whole-seam 任务，定义：

\[
x_g=10m
\]

作为纯确定性 fallback；该 fallback 不产生额外任务可行性。

同时，上下轨都 whole-eligible 的父焊缝可以同时进入 `\mathcal I_{up}` 与 `\mathcal I_{low}`，因为这里的 weighted median 只用于确定 soft handover prior，而不是做唯一任务分配。

该定义保证：

- 同一实例、同一参数下 `x_up/x_low` 唯一且可复现；
- `x_up/x_low` 不依赖任何算法运行结果；
- 不读取 VALIDATION/TEST 的最优解信息；
- GNN 的 `Bx` 静态特征在搜索过程中不会失效。

#### 3.3.2 正式辅助指标的数学定义

为避免“负载、空走、等待”等指标在实现中出现不同口径，统一定义：

对机器人 `r`，其最终 welding blocks 集合为 `Q_r`：

\[
P_r
=
\sum_{q\in Q_r}
\left(
t_{pre}+\frac{L_q}{v_w}+t_{post}
\right).
\]

纯加工负载不均衡：

\[
\boxed{
B_{proc}
=
\max_r P_r-\min_r P_r
}
\]

空走总时间：

\[
\boxed{
T_{empty}
=
\sum_r\sum_{(q_j,q_{j+1})\in route_r}
T^{move}_{j,j+1}
}
\]

总等待时间：

\[
\boxed{
W_{total}
=
\sum_r T_r^{wait}
}
\]

可选拆分数：

\[
\boxed{
N_{split}^{opt}
=
\sum_i
\mathbf 1
[
\text{parent }i\text{ 最终采用非 mandatory split}
]
}
\]

正式 `Cmax` 数值相等容差定义为：

\[
\epsilon_C
=
10^{-9}\max(1,|C_{\max}|)
\]

只用于浮点等价判断，不允许成为“牺牲一点 `Cmax` 换辅助指标”的工程容忍带。

正式词典序比较为：

\[
(C_{\max},
N_{split}^{opt},
B_{proc},
T_{empty},
W_{total},
\text{deterministic ID order}).
\]

cheap screening 可以使用这些量的局部近似增量，但任何近似量不得替代上述正式定义。

### 3.4 canonical solution

每个 parent 最终状态只能是：

```text
WHOLE
X_SPLIT(point)
Y_SPLIT(point)
```

三者互斥。若两个 child 最终回到同一机器人并连续执行，则 canonicalize 回 WHOLE。任何正式评价前必须先 canonicalize，再计算 pre/post 和 `Cmax`。

## 4. 理论碰撞规避

采用 TCP-based planar interference abstraction，不等同于真实机器人本体三维碰撞。

### 4.1 operation 语义

```text
MOVE -> SETUP -> WELD -> POST -> MOVE -> ...
```

`MOVE/WELD` 为线性运动；`SETUP/POST` 为端点静止；`WAIT` 定义为停留在上一 operation 终点。为避免旧方案中“只检查 MOVE/WELD，但又说 SETUP/POST 占位”的语义矛盾，主模型统一规定：

\[
\boxed{\text{MOVE, SETUP, WELD, POST, WAIT 均进入理论干涉检查}}
\]

WELD 与 MOVE 均不可中断；若未来执行会冲突，则整段 operation 延迟到 earliest safe start，不能执行到一半暂停。

### 4.2 连续时间二维判据

对时间重叠区间 `I`：

\[
\Delta x(t)=a_xt+b_x,\qquad \Delta y(t)=a_yt+b_y.
\]

若存在 `t∈I`：

\[
|\Delta x(t)|\le D_x+\epsilon_{num},\qquad |\Delta y(t)|\le D_y+\epsilon_{num},
\]

则判为理论干涉。主值：

\[
\boxed{D_x=D_y=0.50m}.
\]

敏感性检查 `(0.3,0.3)/(0.5,0.5)/(0.7,0.7)/(1.0,0.5)`。正式判定用连续时间解析区间，不用粗时间采样。

### 4.3 同轨不越位与初始状态

\[
x_{R0}(t)+D_x\le x_{R1}(t),\qquad x_{R2}(t)+D_x\le x_{R3}(t).
\]

该约束从计时起点即成立。第一项任务的起点若已经破坏顺序，则该 route combination 不可行，不能利用“初始部署不计时”绕过。

### 4.4 reference scheduler

原方案只写 event-based earliest start，但没有冻结 dispatch priority，导致同一 route 可能因实现顺序不同得到不同 `Cmax`。主 scheduler 改成确定性 list scheduler：

1. 保持每台机器人 route precedence；
2. 对四台机器人 next operation 计算 earliest safe start；
3. 优先调度 earliest safe start 最小的 operation；
4. 并列时依次按 remaining processing load 更大、当前 completion 更大、robot ID 更小处理；
5. 固定该完整 operation 后重新计算其余 ready operations；
6. 直到全部完成。

新的全局 incumbent 才允许有界 critical-priority repair；普通候选不做反复 priority search。reference scheduler 定位为统一确定性协调启发式，不宣称全局调度最优。

### 4.5 independent certifier

certifier 从原始 parent pattern、assignment、route、direction、start/end times 独立检查：parent 覆盖、最多一次 split、child 长度、pre/post 次数、route precedence、non-preemptive、WAIT/SETUP/POST 占位、同轨顺序、连续时间二维干涉、最终 `Cmax` 重算一致。

增加 tiny scheduling oracle：2 台机器人、每台 2～4 个 operations，枚举少量 dispatch/conflict priority，报告 reference scheduler feasibility agreement 与 gap。

## 5. 方向DP优化

固定 route `r=(e1,...,em)`，每条焊缝有两个方向。开放路线不计 home-to-first，因此：

\[
DP_1(0)=DP_1(1)=0.
\]

递推：

\[
DP_i(b)=\min_{a\in\{0,1\}}[DP_{i-1}(a)+T_{move}(E_{i-1}(a),S_i(b))].
\]

不增加 return-home cost。

速度约束：raw insertion / swap / repair position 的 cheap screening 不运行完整 DP；只用局部 orientation-aware transition proxy。一个完整 candidate 被 shortlist 后，只对受影响 route 运行 exact top-1 DP。这样避免取消 `4N` scheduler 后又形成“每个 raw insertion 都 O(m) DP”的新瓶颈。

新的全局 incumbent 且存在显著 waiting 时，才触发 bounded schedule-aware direction refinement：最多选 2 条冲突焊缝，单条 flip，每次重跑 scheduler，单 trigger 最多 `Bdir=4`，并设置每实例总上限。最终正式 incumbent 再次 certifier。

## 6. 实验方法

### 6.1 方法选择：主创新不再是 GAT-PPO operator selection

原方案提出 `GAT/Graph Transformer + PPO + ALNS operator control`。审查后不建议把它作为论文核心创新，因为已有工作已经公开提出：GNN+DRL 用于 ALNS operator selection；DR-ALNS 用 DRL 选择 destroy/repair、调参数和控制接受准则；也已有 GCN/模仿学习学习 LNS destroy operator。

因此单纯把旧 MLP-PPO 换成 GAT-PPO，创新性不足，而且没有直接解决本项目最贵的 `reference scheduler`。

主方法改为：

> **GRC-ALNS：Graph-Ranked, Reference-Certified Adaptive Large Neighborhood Search**

核心：

\[
\boxed{\text{one-time graph encoding}+\text{candidate-level ranking}+\text{top-K exact evaluation}+\text{reference certification}}
\]

学习模块不决定最终 `Cmax`，只学习“当前哪些具体 candidate move 最值得送进昂贵 scheduler”。这与已有 operator-level RL 的学习粒度不同，并直接服务于本项目速度瓶颈。

### 6.2 确定性骨架 SA-OI-ALNS

保留不含学习的 SA-OI-ALNS 作为完整基线与主方法骨架。算子包括：random/critical/high-empty/spatial/interference/split/worst removal；greedy/regret-2/regret-3/load-aware/interference-aware repair；relocate/swap/2-opt/2-opt*/split activate/deactivate/switch；bounded direction/priority repair。`x_up/x_low` 主方法不再 shift。

### 6.3 接受准则

此前方案缺少 acceptance rule。所有 SA-OI-ALNS/GRC-ALNS 统一用 simulated annealing：改善解必接收；劣解按

\[
P_{acc}=\exp[-(C'_{max}-C_{max})/(T\,C_{scale})]
\]

接收。固定 normalization：

\[
C_{scale}=\max\left(1,\frac14\sum_{parent i}(t_{pre}+L_i/v_w+t_{post})\right).
\]

`Cscale` 不随 split pattern 改变，只是尺度，不错误称为严格 lower bound。温度按 reference-evaluation count 衰减。学习模型不控制 acceptance，降低与现有 DR-ALNS 的重叠。

### 6.4 有界 candidate pool

每次 ALNS iteration 只生成：

\[
|\mathcal C_t|\le M.
\]

主实现从 `M=64` 起步，VALIDATION 检查 `32/64/128`。通过 alpha-nearness、spatial kNN、critical robot、conflict adjacency 和 split neighborhood 预筛，不做完整 `O(N^2)` 全邻域枚举。destroy 数量 `q=max(1,round(ρn))` 并做上下界裁剪。

### 6.5 静态图与动态解状态分离

原方案第二个重大 bug 是一方面写“GNN 只 forward 一次”，另一方面又把 current load、waiting 等动态量放入图节点。修正为：

静态 GAT 输入只含不会随搜索改变的焊缝几何、长度、方向角、base process time、固定 `Bx/By` 关系、whole eligibility、split candidate count、局部密度和静态 geometric conflict potential；robot token 只含 rail/left-right/ID。

GAT 每实例只运行一次，缓存 weld embedding `h_i`。

动态 route descriptor 单独计算，并且不能只做 set pooling，因为同一任务集合的不同排序必须被区分。每台机器人动态描述至少包括：节点 embedding pool、first/last embedding、当前相邻 directed transition embedding 聚合、process load、empty travel、waiting、completion、task count、split count、critical conflict count。只更新受 move 影响的 route。

### 6.6 candidate-level graph ranker

#### 6.6.1 candidate 的完整定义

一个 candidate 不是“某个算子名字”，也不是“尚未补全的 partial move”。

在 search state `S_t` 下，一个 candidate `c` 必须是一个**可以被确定性应用到当前 canonical solution 的原子解变换描述**：

\[
\boxed{
c=
(\tau,\mathcal Q_{src},\mathcal Q_{dst},
r_{src},r_{dst},
p_{src},p_{dst},
\pi_{split},
\pi_{dir}^{hint})
}
\]

其中：

- `τ`：move type；
- `Q_src/Q_dst`：涉及的 parent / welding-block IDs；
- `r_src/r_dst`：源/目标机器人；
- `p_src/p_dst`：删除与插入位置；
- `π_split`：WHOLE/X_SPLIT/Y_SPLIT 的具体 pattern 与 split-point ID；
- `π_dir^hint`：只用于 cheap transition proxy 的方向提示，不是最终正式方向。

候选类型至少包括：

```text
INTRA_RELOCATE
INTER_RELOCATE
SWAP
TWO_OPT
TWO_OPT_STAR
SPLIT_ACTIVATE
SPLIT_DEACTIVATE
SPLIT_POINT_SWITCH
```

candidate 必须满足：

1. 从当前 `S_t` 出发应用一次即可得到唯一 provisional solution；
2. 不包含“repair 后再任意搜索若干步”这种不确定过程；
3. 所有 tie-break 唯一；
4. 相同 `S_t + candidate ID` 必须得到 bitwise-equivalent canonical solution（浮点容差除外）。

因此 ALNS destroy/repair 仍负责产生较大的搜索扰动，而 candidate ranker 负责对 repair/local-search 阶段**具体、确定的原子候选**排序。

#### 6.6.2 candidate 生命周期

每个 candidate 依次经历：

```text
C0 raw candidate
→ C1 cheap-feasible candidate
→ C2 rank-scored candidate
→ C3 exact-DP candidate
→ C4 reference-evaluated candidate
→ C5 accepted/rejected candidate
```

- `C0→C1`：检查 parent coverage、one-split、child length、robot eligibility、route index 等便宜约束；
- `C1→C2`：构造 ranker 特征并 batch score；
- `C2→C3`：只对 shortlist 受影响 routes 运行 exact top-1 DP；
- `C3→C4`：运行 reference scheduler，得到正式 `Cmax` 或 `INFEASIBLE`；
- `C4→C5`：由统一 SA acceptance 决定是否更新 current solution。

只有 `C4` 具有正式 objective。

#### 6.6.3 candidate identity 与去重

定义 candidate key：

```text
(
 current_solution_revision,
 move_type,
 sorted affected parent IDs,
 source/destination robot IDs,
 source/destination route positions,
 split-pattern ID / split-point ID
)
```

同一 iteration 中相同 key 只保留一次。

若不同 move 描述 canonicalize 后得到完全相同 solution，则在 reference scheduler 前用 canonical solution hash 做 exact duplicate memoization，只评价一次。

每个 candidate 包含 move type、受影响任务 embedding、source/destination robot descriptor、局部 travel delta、load delta、split delta、soft-boundary relation、cheap conflict delta 和插入位置。

ranker 输出 `sθ(c|St)`。流程：

```text
bounded candidates
 -> cheap feasibility
 -> batched graph rank score
 -> top Kdp
 -> exact DP on affected routes
 -> top Kref
 -> reference scheduler
 -> best exact candidate
 -> SA acceptance
```

初始建议 `Kdp=8, Kref=2`，VALIDATION 检查 `Kref=1/2/4`。


### 6.6.4 ranker 与 SA 探索机制的解耦

若 ranker 永远只把最高分候选送入 reference scheduler，则 SA 虽然允许接受劣解，却实际上**看不到 ranker 判为低分但具有长期探索价值的候选**，会造成 exploitation bias。

因此明确：

\[
\boxed{\text{ranker 只控制 evaluation budget，不控制 SA acceptance}}
\]

并为 exact shortlist 保留强制探索配额。

主方案：

\[
K_{ref}=2.
\]

普通 iteration：

```text
1 个 exploit candidate：
    exact-DP 后 rank score 最高

1 个 exploration candidate：
    从剩余 Kdp-1 candidates 中按 exploration policy 选择
```

探索候选不允许再次选择 rank top-1。

主 exploration policy 使用：

\[
P(c)
\propto
\exp
\left(
\frac{\tilde s_\theta(c)}{\tau_{rank}}
\right)
+
\lambda_{nov}\,Novelty(c)
\]

其中 `Novelty(c)` 根据最近 `H` 次 accepted/evaluated move 的：

- move type；
- affected parent；
- source/destination robot；

计算。

为避免再引入复杂可调模型，第一版可以简化为：

```text
50%：从非 top-1 的 Kdp shortlist 中按 softmax(score) 采样
50%：从非 top-1 shortlist 中均匀采样
```

随机数由 algorithm seed 固定。

当 search 连续 `S_stag` 次 reference evaluations 未改善 best solution 时，进入短暂 diversification：

```text
exploration candidate 优先选择 novelty 最大者
```

`S_stag` 只在 VALIDATION 冻结。

SA acceptance 始终在 reference `Cmax` 得到之后执行：

- exploit candidate 可能被接受或拒绝；
- exploration candidate 同样可能被接受或拒绝；
- 两个 candidate 都 reference-evaluated 后，先按正式词典序确定本 iteration 的 proposal，再执行 SA acceptance；
- 不允许 rank score 直接进入 acceptance probability。

这使：

> ranker 负责“值得花 evaluator 预算看谁”，SA 负责“已经看过以后是否接受”。

#### 6.6.5 防止 ranker feedback loop 的训练采样

offline ranker 数据不能只来自“旧 ranker 已经挑中的候选”，否则会形成自我强化的 selection bias。

TRAIN 数据至少包含：

```text
40% heuristic-top candidates
30% uniform-random candidates
20% novelty/diversification candidates
10% near-tie/hard-negative candidates
```

比例可以在 VALIDATION 小幅调整，但必须保证存在固定的 ranker-independent exploration data。

正式测试中 ranker 不更新。

### 6.7 训练改为 learning-to-rank

主训练不再用在线 PPO。只在 TRAIN 上收集 SA-OI-ALNS search states；对每个 state 采少量 candidates，离线 reference evaluation 得到真实 `ΔCmax`，训练 pairwise/listwise ranking。可增加 feasibility classification 和 normalized `ΔCmax` regression 辅助头，但最终 shortlist 仍由 rank score 决定。

训练数据从约 `1e4` labelled candidates 起步，只在 VALIDATION 未饱和时扩展，并设置硬上限，禁止生成全空间 catalog。

旧 MLP-PPO 与 GAT-PPO operator controller 只保留为内部学习基线，不再作为主方法。

### 6.8 正式速度契约

正式测试计时包括：problem-specific preprocessing、split candidate construction、一次 GAT forward、initial solution、search、reference scheduling、final certification。只排除 Python process startup、权重从磁盘加载和 offline training。

主 runtime benchmark 用 CPU 单进程固定线程；训练可用 GPU。固定时间：`1 s / 5 s / 30 s`，5 s 为 primary。必须报告 time-to-target、Nref、candidate count、GNN/ranker/scheduler 时间。

禁止隐藏：全 `x_up/x_low` cell、全 split grid、每 raw insertion full DP、每 raw insertion reference scheduler。

### 6.10 小规模完整问题 exact / lower-bound 验证

仅有 tiny scheduler oracle 还不够，因为它只验证“固定 route/direction 后怎样协调”，不能回答完整 MRTA + split + sequencing + direction 是否接近最优。

因此新增两级验证。

#### 6.10.1 Full exact micro-instances

对很小实例，例如：

```text
N_parent <= 6
```

构造与正式问题**完全相同语义**的 exact branch-and-bound / exhaustive solver：

枚举或分支：

```text
WHOLE / legal X_SPLIT / legal Y_SPLIT pattern
robot assignment
route permutation
weld direction
```

对每个完整离散解，使用一个 exact micro-scheduler：

- 枚举有限 dispatch/conflict-priority alternatives；
- 使用与正式 certifier 相同的连续时间 interference checker；
- 求该离散解的最小协调 `Cmax`。

结合：

- current best incumbent；
- process-load lower bound；
- route-length lower bound；
- symmetry breaking；

进行 branch-and-bound。

对这些 micro instances 得到：

\[
\boxed{C_{\max}^{OPT}}
\]

并报告：

\[
Gap
=
\frac{C_{\max}^{method}-C_{\max}^{OPT}}
{C_{\max}^{OPT}}\times100\%.
\]

该实验验证整个方法，而不仅仅是 scheduler。

如果 `N<=6` 仍过慢，可以先从 `N<=4/5` 建立 exact oracle，再逐步扩展；不能为了宣称 exact 而使用未经证明的近似模型。

#### 6.10.2 Analytical lower bound

对中大实例定义一个不依赖算法的基础下界。

每个父焊缝至少需要一次 pre/post，并完成全部焊接长度，因此总 processing work 至少为：

\[
W_0
=
\sum_i
\left(
t_{pre}+\frac{L_i}{v_w}+t_{post}
\right).
\]

所以：

\[
LB_{work}
=
\frac{W_0}{4}.
\]

由于每个 parent 最多只能形成两个并行 blocks，因此任意父焊缝 `i` 的完成跨度不可能小于：

\[
LB_i^{parent}
=
t_{pre}+t_{post}+\frac{L_i}{2v_w}.
\]

于是：

\[
LB_0
=
\max
\left(
LB_{work},
\max_i LB_i^{parent}
\right).
\]

该下界忽略：

- empty travel；
- interference waiting；
- robot eligibility；
- split-point restriction；

因此一定不会高估真实 optimum，但可能较松。

#### 6.10.3 Eligibility-aware LP lower bound

进一步建立一个 assignment relaxation：

- 忽略 route order、empty travel 和 interference；
- 保留 upper/lower/robot eligibility；
- 保留每个 parent 的合法 WHOLE/X_SPLIT/Y_SPLIT pattern；
- 将 pattern/assignment binary variables 放松到 `[0,1]`；
- 最小化最大机器人 process load。

其最优值记为：

\[
LB_{LP}.
\]

正式中大实例下界：

\[
\boxed{
LB
=
\max(LB_0,LB_{LP})
}
\]

报告：

\[
Gap_{LB}
=
\frac{C_{\max}^{method}-LB}{LB}\times100\%.
\]

`LB` 只用于质量解释，不参与算法 reward、ranker label 或参数选择。

#### 6.10.4 exact / lower-bound 验证的作用

最终论文至少同时给出：

1. micro instances 的 exact optimality gap；
2. normal instances 的 lower-bound gap；
3. reference scheduler 对 tiny scheduling oracle 的 scheduler-only gap。

这样可以把三个不同问题分开：

```text
搜索器离全局最优有多远？
scheduler 本身损失多少？
大实例虽然未知最优，但离有效下界有多远？
```


## 7. 对比实验

### 7.1 Adapted-HGA

Paper-aligned 版本保留 population、route-based crossover、population management、relocate、swap、two-consecutive swap、2-opt、2-opt*、alpha-nearness，原文参数 `μ=20, λ=10, α=20` 作为复现起点。

Common-model 版本共享四机器人问题、whole/split feasible set、setup/post、bidirectional semantics、motion model 和 reference scheduler/certifier；HGA 保留自己的方向处理与搜索，不把本文 DP 强行塞给 HGA 后再当本文贡献。

### 7.2 Adapted-WAG+VNS

保留 multiple WAG、split/recombine、nearest addition、farthest insertion、two-direction insertion、2-opt、factorial edge combination、move/swap/LNS/VNS。原文 `n=10,p=50%,Imax=500` 为复现起点。

Common-model 扩展为双滑轨四机器人，使用相同 one-split-per-parent、soft Bx/By、setup/post 和最终 reference scheduler；保留自己的 route/direction/VNS 逻辑。

### 7.3 两层验证

A. Paper-aligned sanity check：证明重实现没有明显削弱原文算法。

B. Common-model 正式排名：

```text
Adapted-WAG+VNS
Adapted-HGA
SA-OI-ALNS
GAT-PPO-ALNS（内部 operator-control baseline，可选）
MLP-Ranker-ALNS
GRC-ALNS
```

全部共享问题、可行域、时间模型、理论干涉、certifier、Python、CPU/thread、wall-clock。允许共享 distance/static geometry cache 和 exact duplicate-solution memoization，但不允许只有提出方法拥有改变搜索逻辑的 hidden shortcut。

### 7.4 主要消融

```text
A1 no optional split
A2 terminal direction vs DP-in-search
A3 DP-only vs bounded schedule-aware direction repair
A4 full-reference vs learned top-K screening
A5 MLP ranker vs graph ranker
A6 operator-level GAT-PPO vs candidate ranking（可放附录）
A7 Kref=1/2/4
A8 δ/Lmin 与 D sensitivity
```

### 7.5 指标与统计

Primary：`Cmax`。报告每实例 seeds 聚合后的 median、paired relative improvement、1/5/30s anytime quality、time-to-target。

Efficiency：`Nref`、candidate count、ranking time、DP time、scheduler time、one-time GNN time、memory。

每个 stochastic method / instance 至少 5 seeds。同一实例先聚合 seeds，再以 instance/family 为统计单位；不能把 `5 seeds × N instances` 当成 `5N` 个独立问题。可用 paired Wilcoxon、paired bootstrap CI、median relative improvement。

主速度结论只来自 same Python + same CPU/thread + same timing boundary，原论文 C++ 时间只作外部数量级参考。

## 8.实施计划

### 8.1 公共模型正确性

先完成 frozen Bx/By、WHOLE/X_SPLIT/Y_SPLIT canonicalization、setup/weld/post、open-route initial feasibility、continuous interference checker、WAIT/SETUP/POST occupancy、reference scheduler、certifier、direction DP。

同时实现并冻结：

```text
x_up/x_low weighted-median definition
official auxiliary metrics
candidate data structure / candidate key
DEADLOCK / INFEASIBLE / NUMERIC_FAILURE 三类 scheduler status
wait-for graph
bounded deadlock repair
```

完成：

```text
length conservation
one split
child length
merge
DP vs 2^m
continuous conflict
first-task order
non-preemptive
independent Cmax
candidate deterministic replay
candidate canonical duplicate detection
finite-ESS test
constructed deadlock test
deadlock-repair success/failure test
```

以及 tiny scheduler oracle。

### 8.2 高速 deterministic backbone

实现 bounded candidate pool，确认 ordinary raw candidate 不调用 scheduler、不运行 full DP；每 iteration 的 Kref 有硬上限。记录 iterations/s、candidate/s、Nref/s、scheduler mean/p95、DP time。

### 8.3 实现 HGA/WAG

先 paper-aligned sanity，再 common-model。若 SA-OI-ALNS 在 VALIDATION 5s 明显落后 HGA/WAG，暂停学习模块，先修 deterministic neighborhood、repair 和 evaluator。

### 8.4 构建 ranker 数据

只用 TRAIN。

沿 SA-OI-ALNS trajectory 采 representative states，生成 bounded candidate sets，只精确标注小批候选；从约 `1e4` candidates 起步，必要时再增加，不生成全空间 catalog。

训练采样必须混合：

```text
heuristic-top
uniform-random
novelty/diversification
near-tie hard negatives
```

禁止只标注当前 ranker/heuristic 已经认为最好的候选。

数据记录至少包含：

```text
state_id
candidate_key
candidate features
reference Cmax
feasible/infeasible status
ΔCmax relative to state
move type
exploration source
```

这样可以审计 selection bias，并复现 ranking labels。

### 8.5 MLP ranker

先验证 learned screening 本身是否能在保持质量的同时降低 Nref。

### 8.6 Graph ranker

实现 static weld graph、one-time GAT、dynamic route transition pooling、candidate batch scorer、top-K shortlist。必须测试同一任务集合不同 route 顺序产生不同动态描述，且 GAT 每实例只 forward 一次。

### 8.7 可选 GAT-PPO operator baseline

只做最小 literature-aligned 版本，用于比较 generic operator selection 与 candidate-level ranking；时间有限时可放附录或删除，不影响主方法完成。

### 8.8 速度验收

审计 preprocessing、GAT、candidate generation、ranking、DP、scheduler、certifier。验收：无旧 4N、无全 cell/split grid、无无界 N² 全邻域、Kref 有硬上限、GNN+ranker 占 5s 小比例、与 Python HGA/WAG 同数量级。

### 8.9 小规模完整 exact / lower-bound 验证

在正式 ID_TEST 前先完成：

```text
tiny scheduler oracle
full exact micro-instance solver
analytical LB0
eligibility-aware LP lower bound
```

验收：

- full exact solver 与 brute-force 更小实例一致；
- `LB0 <= OPT`；
- `LBLP <= OPT`；
- 所有正式方法输出都 `>= LB`；
- micro instances 报告真正 optimality gap。

如果 lower bound 被发现高于已知 exact optimum，立即停止正式实验并修正 bound。

---

### 8.10 数据冻结与正式测试

旧 PPO/V10 数据只做 development/regression。新数据按 family 隔离：TRAIN、VALIDATION、ID_TEST、OOD_SIZE、OOD_GEOMETRY、BOUNDARY_STRESS。VALIDATION 只用于 `M/Kdp/Kref/GAT size/rank loss/ALNS params`。冻结后一次性运行 ID_TEST。

### 8.10 论文决策门

若 `GRC-ALNS > SA-OI-ALNS > HGA/WAG` 且 `Nref` 显著减少、time-to-target 不慢，则主贡献为 graph-ranked reference-certified search。

若 `GRC-ALNS ≈ SA-OI-ALNS > HGA/WAG`，论文回退 SA-OI-ALNS，学习模块只作附加实验。

若 `SA-OI-ALNS < HGA/WAG`，停止正式测试，继续优化 deterministic backbone。

最终科学定位：

\[
\boxed{\text{soft one-time handover}+\text{orientation-integrated routing}+\text{continuous theoretical scheduling}+\text{graph-ranked screening}+\text{reference certification}}
\]

神经网络替代的是大量无效候选的昂贵协调评价，不替代最终调度器。最终正式 `Cmax` 始终由 reference scheduler / certifier 给出。
