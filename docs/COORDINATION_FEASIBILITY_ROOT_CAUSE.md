## 1. 结论

根因是**初始化路线顺序失配**，不是机器人资格、任务分配合法性、首方向选择，也没有证据表明正式 32 次恢复预算是本轮主要瓶颈。

- MEDIUM_02 与 LARGE_04 的 REGION 分配分别保持原四机器人加工负载不变，仅重排既有任务并重新执行原方向 DP，就能在原 B32(32) 下得到独立认证解。
- 同一分配和同一路线下，最多 16 个合法首方向配置不能救活任何原失败候选。
- 同一分配、路线和方向下，将离线恢复预算改为 128/256，没有为任何原失败候选增加可行解；MEDIUM_02 在 44 次、LARGE_04 在 110 次后前沿耗尽，仍为 DEADLOCK。这不是数学不可行证明，只能排除“单纯把预算从 32 增至 128/256”这一解释。
- 最小修复只替换初始化五候选中的 `X_ORDER_AWARE` 槽位：保留 REGION 的 WHOLE/Y/X、轨道与机器人归属，用已有 farthest insertion 加 bounded 2-opt 重排四条路线。构造预算仍为 5，`kinit_ref` 仍为 5，正式 B32 仍为 32。
- 12 组真实 60 秒开发配对为 **4 胜 / 8 平 / 0 负**；配对 Cmax 平均变化 **-5.03%**，中位变化 **0.00%**，最大退化 **0.00%**。

因此保留该修复为**默认关闭的可选增强**。它已提供多个 consumed-development 几何上的证据，但没有新的独立测试，不能替代既有 REGION_FAST_HEURISTIC 的正式独立结论。

## 3. MEDIUM_02 与 LARGE_04 的阻塞证据

### MEDIUM_02

- 固定 REGION 加工负载：`[1985.900, 2019.363, 3534.252, 3570.587] s`。
- 原 DP 方向可行，但 B32(32) 的最终等待关系包含 `R0 -> R1` 与 `R3 -> R2`；R3 被 R2 的 `POST/WELD/MOVE/SETUP/WELD` 操作链阻塞。
- 16 个合法首方向组合全部 DEADLOCK，分支点和阻塞结构不发生实质改变。
- 只重排路线后，6/8 个候选独立认证。预设 `TWOOPT_FARTHEST` 路线得到 `4824.741 s`；离线事后最佳 `ALL_ASC` 为 `4597.133 s`。
- 固定原输入的 128/256 次诊断均在 44 次 rollout 后前沿耗尽，耗时约 `0.36 s`，仍 DEADLOCK。

### LARGE_04

- 固定 REGION 加工负载：`[4470.060, 4720.725, 6092.599, 6739.637] s`。
- 原 DP 方向可行，但 B32(32) 的最终等待关系含 `R0 -> R1`；R0 被 R1 的连续焊接、移动、SETUP/POST 操作链阻塞。
- 16 个合法首方向组合全部 DEADLOCK。
- 只重排路线后，`TWOOPT_FARTHEST` 在 baseline rollout 内直接 FEASIBLE，独立认证 Cmax 为 `6846.505 s`、WAIT 为 `0 s`。
- 固定原输入的 128/256 次诊断均在 110 次 rollout 后前沿耗尽，调度耗时约 `2.28 s`，仍 DEADLOCK。

这些结果证明**均衡任务分配本身可以形成合法协调调度**，但不证明原固定路线在数学上无可行时序。原 B32 的 DEADLOCK 仍只是给定路线、方向和有限恢复策略下没有找到可行时序。

## 4. 唯一代码修复

修改函数：`_construct_region_coordination_route_reordered_initialization()`，并通过 `initialization_coordination_route_reorder=False` 显式开关接入原初始化组合。

实现约束：

- 先调用原 `_construct_region_cooperative_initialization()`；
- parent、WHOLE/Y/X pattern、轨道归属和机器人归属全部保持不变；
- 每台机器人只对自己的既有任务执行 `_farthest_insertion_route()` 和 `_bounded_two_opt()`；
- 完整结果重新 `canonicalize()`，并逐 block 比较修复前后机器人归属；
- 开关启用时只替换 `X_ORDER_AWARE` 槽位，不增加第五个以外的构造；
- 不修改方向 DP、B32、certifier、SA、M192、Kdp8、Kref2/Kref_total4；
- 与 SAME_RAIL 共用同一替换槽位，禁止同时启用；默认关闭时旧行为不变。

采用固定 `TWOOPT_FARTHEST`，不是逐实例选择离线最佳路线。修复质量门槛只使用 consumed-development：N35-S1、N85-I12、HW_20262232 出现严格认证改善；MEDIUM_02/LARGE_04 不参与版本选择。

## 7. 墙钟与认证

两种方法均使用同一个 `HardDeadlineReferenceEvaluator`。24 个 run 的最后一次跨截止 reference 都被父进程终止，各自只保留截止前已独立认证 incumbent。

- 原方法最大实际返回时间 `62.565 s`，最大 overshoot `2.565 s`；
- 修复方法最大实际返回时间 `63.912 s`，最大 overshoot `3.912 s`；
- 未再出现历史上 400 秒以上的不可控阻塞；
- 所有 `Cmax@60` 均来自 60 秒前已经认证的 best，截止后结果未回填。

返回时间仍包含 Windows 进程终止和 IPC 清理尾部，因而不是严格等于 60.000 秒；但它不改变两组 Cmax 的共同截止语义。

## 9. 保留/停止决策

保留默认关闭的 `REGION_COORDINATION_ROUTE_REORDERED` 作为开发增强，冻结当前固定构造，不继续调路线权重、候选数量或 B32 预算。

本轮证据足以支持以下方法陈述：REGION 的困难失败并非主要来自缺少均衡任务分配，而是均衡分配配套路线顺序可能形成 B32 难以协调的阻塞结构；一个不改变任务归属的固定路线重排能够把该分配转化为认证调度，并在统一 60 秒预算下改善多个 development 几何。

但证据尚不足以形成新的独立性能主张。若论文需要将该修复升级为正式主方法，下一步只能使用未参与本轮开发的新几何做独立验证。本轮停止算法扩张：不开发 CRRR/JRRB 后续版本，不修改 C2/C4，不增加邻域，不修改正式 B32，也不训练新 GAT。GAT V05 及其接口保持不变。
