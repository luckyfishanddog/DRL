# B32安全剪枝与规则引导GNN实验

## 实施边界与剪枝依据

执行环境为D:\pybullet_test\.venv\Scripts\python.exe，工作目录为项目DRL。固定四机器人双轨、min_child_length=0.50m、delta_x=delta_y=0.50m、FORMAL_SCOPE_V2和B32最多32次恢复rollout。MODE_NEW的父选择、模式调整、方向联合插入和严格Cmax接受不变，WAG/HGA代码不修改。
对当前完整路线及方向，LB=max_r(P_r+M_r)。P由config.process_time累计SETUP/WELD/POST，M为当前方向下的相邻焊缝空走；既有开放路线不计首任务进场或返家。B32只增加非负等待，故LB≤真实Cmax。
搜索沿用epsilon=1e−9×max(1,Cmax_best)，LB≥Cmax_best−epsilon时跳过B32。初始化原来按精确最小Cmax选择，因此采用更保守的LB≥Cmax_best，保留小于搜索epsilon的初始化改善。没有可行初解时继续B32；跳过项标记PRUNED_BY_CMAX_LB，Cmax留空。
实现复用OrientedRouteState.loads和arc_costs；未使用round后的oriented_time_score或exposure_score。RepairResult/JointCompletionResult保留已有路线状态以避免重复计算。报告数值为显示取整，CSV保留原始精度。

主要修改位于src/mrta_search/lns.py、src/mrta_search/gnn_constructor.py、scripts/run_gnn_multi_initial.py、scripts/run_joint_oriented_repair_pilot.py和scripts/run_gnn_shared_construction.py。scheduler.py只为既有SchedulerProfile补充基准/完整恢复计时，PreparedDispatchProblem缓存与正式调度策略保留。

## 扩展训练

现有权重验证中，规则引导对CURRENT/MRV初始均8胜，最终分别7胜1负、8胜；24/24可行，高于RULE的21/24，因此进入一次扩展训练。相对RULE仍不能宣称Cmax整体优势。
原训练几何保留21个、去重教师110个；静态新增PPO训练几何40个，与原几何重复数为0。
新增几何取得可执行教师：40/40。RULE和MODE_NEW共享一次真实初始化；缺少教师时使用原WAG/HGA，不改变对照算法。只使用已记录的B32 FEASIBLE方案，离线重放动作时不再B32或独立认证；不能重放的教师保留失败原因，不伪造动作标签。

## 失败分析与下一步决定

1. **保留B32安全剪枝。** 固定工作量结果与接受轨迹一致，60秒比较增加迭代并取得9胜3平。恢复策略、合法候选和Cmax目标均保留；测量不支持为模板生成另加缓存。
2. **规则融合优于当前GNN，但仍没有建立对RULE的整体Cmax优势。** 现有权重融合对CURRENT初始8胜、最终7胜1负，中位改善24.772%/2.703%；对RULE的7个有效几何配对，初始0胜7负、最终2胜1平4负，最终中位改善−0.362%。融合24/24可行，RULE为21/24，故成功样本的总体均值不能直接横比。
3. **单独MRV不够。** 其N31–50第二个几何和较大几何终解明显较弱；N71–90首个几何的一次初始化中，三个候选均被B32返回DEADLOCK。规则融合在相同合法池内改善了排名，但P+MOVE排序与网络排名都不能保证更低真实协调Cmax。
4. **初始化失败来自有界候选菜单耗尽。** RULE在N31–50首个几何三种子共24次初始B32评价均返回DEADLOCK；未取得任何可行初解时没有启用下界剪枝。该现象不等于证明几何不可行，其他GNN方法在同几何可行。
5. **本次扩展训练新增收益不足，停止继续加训。** 相对未扩训融合模型，初始为0胜7平1负、中位改善0%；最终4胜2平2负、中位改善仅0.023%。7个几何初始中位Cmax完全相同，不能把不同运行阶段的迭代速度差异全部归因于训练。对RULE最终仍为3胜4负、中位改善−0.316%，尚不支持以新权重替换主方法。原权重与融合结果保留，新权重保存为本次研究证据，不继续堆叠模块。
主方法保留RULE初始化的MODE_NEW并使用已证明等价的B32安全剪枝；规则融合保留为开发候选。8个保留holdout维持未打开状态，本报告仅为既有验证集上的开发证据。
