# CRRR 结构性搜索邻域开发结果

## 结论

本轮选择 **B：CRRR 没有形成稳定有效收益，不默认启用**。实现保留为显式 `enable_crrr=True` 的开发消融；生产默认仍关闭。原因不是 CRRR 不能构造合法解，而是其收益高度集中且伴随不可接受的搜索轨迹回归：

- REGION+CRRR+HEURISTIC 对 REGION+原LNS+HEURISTIC：**2胜/8平/2负**，配对相对变化中位数 **0.00%**、均值 **+1.60%**；S1 seed 20261702 恶化 **+20.95%**。
- REGION+CRRR+GAT V05 对 REGION+原LNS+GAT V05：**1胜/7平/4负**，中位数 **0.00%**、均值 **-0.62%**；唯一胜局是 I5 seed 20261702（**-22.81%**），但另一 I5 seed 恶化 **+7.20%**。
- 2272 次 CRRR 在线尝试中只有 **3 次严格 Cmax 下降**，三次全部来自 I5 的 GAT 运行。不存在“多个独立几何实例均获得真实改善”的证据。
- 全部 24 个新增 60 秒运行和复用的 24 个原 REGION 对照均有独立认证结果；本结果只属于 consumed-development，不能表述为新的独立测试优势。

## 实现及其与原 LNS 的区别

CRRR 仍使用 `CompleteSearchCandidate`、`CandidateSourceKind.LNS_REPAIRED`、`CompleteCandidateIdentity` 与 `canonicalize()`。启用后每轮保持 **144 atomic + 40 原 LNS + 8 CRRR = M192**；Kdp8、Kref2、Kref_total4、SA、direction DP、B32、certifier 与 REGION 初始化均未修改。

CRRR 的结构性差异为：

1. `WAIT_BOUNDARY` 从已认证 schedule 的 WAIT 区间出发，用同机器人 WAIT 前后真实 WELD 定位 parent，并加入同轨伙伴在该时段附近的空间上下文；WAIT 只用于选择区域，不被当作冲突因果证明。
2. `LOAD_BOUNDARY` 从完工最晚机器人与同轨伙伴的 X 方向任务交界选择 2–6 个空间/路线邻接 parent，而不是选加工时间最大的 parent。
3. 对整组 parent 同时移除并执行四类有界方案：同轨连续迁移、边界交换、WAIT 区域局部重排、合法跨轨重分配；其余任务顺序保留，通过有界插入恢复完整路线。
4. 廉价修复分数同时包含最大加工负载、负载差、空走、同轨 X 包络重叠和首任务顺序风险。空间重叠从未被当作不可行判据。
5. 候选必须至少有两个 parent 的机器人归属或路线邻接关系发生变化。拆分模式不变；X_SPLIT child 身份固定；direction/B32 只在原 C2/C4 后调用。

示例：S1 的 LOAD_BOUNDARY 将 `inst0003|group=801-FR322A.dxf|row=0000` 与 `...|row=0003` 在 R0/R1 边界联合重分配，2 个 parent 的归属和邻接均改变，离线独立认证 Cmax 为 4795.627s（初值 4956.890s）。I5 的 WAIT_BOUNDARY 对 `inst0025|group=165-SR2A.dxf|row=0000/0002` 做局部邻接改变；另一 LOAD_BOUNDARY 三-parent 方案取得 3712.464s（初值 4141.496s）。这些都不是原 `CRITICAL_LOAD_REMOVAL + REGRET_2_REPAIR` 的改名。

原 LNS 的 160 次尝试得到 91 个唯一候选（56.9%），22 个进入 C2；CRRR 的 32 次尝试得到 29 个唯一候选（90.6%），却 0 个进入首轮 C2。S1/I5 明确存在被漏掉的认证改善候选，因此主要首轮失败环节是既有 cheap/C2 排序，而非构造合法性。本轮按冻结条件没有修改或训练 C2/C4。

## I5、S1、I6、I9 解释

- **I5**：GAT seed 20261702 将 WAIT 从原 C 的 1133.396s 降到 37.137s，Cmax 3959.926→3056.716s；但 seed 20261701 WAIT 525.118→881.965s，Cmax 3718.388→3986.164s。CRRR 确实可减少协调等待，但方向不稳定。不能把 `Cmax-max_process_load` 全部解释成 WAIT。
- **S1**：离线 CRRR 可将初始化 4956.890→4795.627s，但在线 CRRR 在两种排序下均无接受项；它没有独立证明跳出串行结构。B 的一个 seed 反而退化 20.95%。
- **I6**：离线最优等于初始 3495.628s；在线 CRRR 没有严格下降。主要是 CRRR 认证质量有限（smoke 为 1 FEASIBLE / 5 DEADLOCK），不是只因无法生成候选。
- **I9**：GAT 两个 seed 共接受 18 个 CRRR 候选，但严格 Cmax 改善为 0；这验证了“接受/同 Cmax 次级指标改善”不能记作 Cmax 下降。强初值下已评估候选的 Cmax 确实不优。

## 计算开销、失败记录与 HGA/WAG 参照

CRRR 总生成时间 10.734s / 2272 次，平均 **4.72ms/尝试**。HEURISTIC 与 GAT 新运行平均实际 runtime 分别 63.660s 与 63.600s；最大 overshoot 9.338s 与 7.279s，均沿用原“完成当前迭代但不回填 60 秒结果”的截止语义。GAT 推理总计 35.206s。CRRR 自身开销不大，但替换 8 个原 LNS 会减少每轮原结构候选，已导致可见机会成本。

首次 GAT 执行因 CRRR `repair_trace` 未保持冻结 V05 的原 LNS 嵌套形状而产生 12 条 `EXECUTION_ERROR`。这些记录完整保存在 SQLite 的 `crrr_search_failures`；修复只恢复 provenance 兼容，不改变候选、checkpoint 或排序逻辑，随后仅重跑受影响的 12 个 GAT run。

既有 HGA/WAG 开发 seeds 为 20261401/20261402，与本轮 20261701/20261702 不同，且 HGA/WAG 使用 N35-S3 而本轮使用 S1，所以不能作严格配对。仅对 5 个重合几何按各自两 seed 中位数作非严格参照：CRRR+HEURISTIC 相对 HGA/WAG 的实例层中位差分别为 -7.97%/-1.74%，CRRR+GAT 为 -3.92%/-1.83%。这不推翻旧正式 375-run 结论，也不能据此声称 CRRR 已稳定超过 HGA/WAG。

## 最终回答与停止条件

1. CRRR 真正联合改变 2–6 个 parent 的归属/邻接，并与原 critical-load destroy/greedy-regret repair 有实质区别。
2. I5 存在一次显著 WAIT/Cmax 改善，但另一 seed 反向恶化；不稳定。
3. S1 未由在线 CRRR 跳出，I6/I9 没有 CRRR 严格下降。
4. CRRR 构造/唯一率高，但在线总漏斗为 2272→2066→1855→88(C2)→44(C4/B32)→27接受→3严格改善。
5. CRRR 平均 4.72ms/尝试，计算本身不是主要瓶颈；主要限制是 C2/C4 入口和已认证候选的跨状态质量。
6. B vs A、D vs C 都不支持稳定收益，且存在严重 N35 回归；D vs B 也不支持稳定 GAT 增量。
7. **CRRR 不成为默认邻域**；REGION 初始化继续保留，CRRR 仅保留为显式开发消融，不继续堆叠新邻域，也不重训 GAT。
8. 当前不具备冻结“增强型搜索方法”为论文新默认的条件。论文主体应继续如实强调区域初始化的确定性收益、学习排序的候选筛选作用及其稳定性限制；若未来研究 CRRR，只能在新的开发数据上单独解决结构候选的 stage-available 排序，不得用旧 ID_TEST 调参。
