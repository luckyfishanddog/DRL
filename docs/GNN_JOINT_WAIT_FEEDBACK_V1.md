# GNN-V2：调度等待反馈选区实验

## 实验设置

六个现有 MLP_DEV，seed=20261027，CPU单线程；加载 `models/gnn_joint_repair_v2.pt`，未训练或生成教师数据。
每实例只计算一次共同 Beam 初解，并把同一个初解对象交给 BASE 和 WAIT；模型、联合插入、B32、24轮预算均相同。
原定选区 RANDOM/TRAVEL/LOAD 循环；q序列为 [4,4,4,8,8,8] 重复4次；种子为 seed+实例原索引×10000+零基迭代号。
WAIT每轮读取当前已接纳调度，累计 duration>numeric_epsilon 的 WAIT。存在正WAIT才覆盖为WAIT_ANCHORED；无WAIT保留原定选区；WAIT部分解不可用则回退本轮原定选区。
仅完整候选调用一次B32；判断WAIT不调用调度器。接纳沿用原实现 Cnew<Cold−1e−9×max(1,Cold)。方向和邻块翻转仍在联合插入中决定。
WAIT_ANCHORED 是等待时空关联代理，未识别真实因果阻塞操作。旧Regret-2和静态WAIT试验结果未混入本次数据。
运行时间仅含24轮选区、补全、B32和记录，不含共同Beam、Excel及模型加载。CSV每行对应一条24轮轨迹，trace保留逐轮原定/实际选区、WAIT、回退、移除集合、候选及接纳状态。

本次运行日期为2026-11-01。BASE保留原搜索行为；前五例的共同初值及24轮原有轨迹字段与原V2结果逐项相同。g45本次现有Beam生成初值为5549.958352s，旧V2报告为5447.517980s，因此本轮未完整复现g45的历史数值。初解生成器和B32均未修改，差异来源尚未单独定位；本次两方法确实共用同一个新计算的Beam初解，g45的结论仅适用于此共同初值。

首次完整运行在最终写CSV时被文件权限拒绝，未能保存逐轮记录；修复输出权限后，按相同设置完整重复一次并保存，未合并两次候选或按较好终值挑选。两次控制台记录的六个共同初值及12个最终Cmax一致。以下表格只使用后一次完整保存的12条轨迹：搜索实际288次B32，共同Beam32次；连同首次保存失败的计算，实验实际总调用为640次。每条独立搜索始终为24轮，每轮至多一次B32。权限失败导致了额外计算，已与正式比较预算区分。

## 失败与结论

|方法|构造失败|DEADLOCK|其他调度失败|接纳总数|搜索B32成功/调用|24轮总秒|
|---|---:|---:|---:|---:|---:|---:|
|GNN-V2-BASE|0|30|0|9|114/144|63.287|
|GNN-V2-WAIT|0|45|0|10|99/144|66.998|

最终以Cmax为准；WAIT下降或某轮接纳本身不代表超过BASE。DEADLOCK仅表示当前B32搜索未找到调度，不能证明数学不可行。
这是一组固定种子、六个DEV实例的控制变量实验，不能据此宣称跨种子的稳定性。

g33的WAIT组第1轮把Cmax降低110.287342s，WAIT从726.318570s降到24.868170s，但此后23轮只有1次可调度且恢复当前目标值，其余22次DEADLOCK。q8全部12次失败；24次移除集合各不相同，不能解释为重复了同一个集合。最终仍比BASE差176.842618s，明显降低WAIT并未带来更好的最终Cmax。

g31的WAIT组21/24次可调度，但最好候选3126.835182s仍高于当前3126.806539s，没有接纳，24次移除集合也各不相同。BASE第2轮便通过TRAVEL消除90.178126s等待，之后继续接纳到3071.671087s。有WAIT就覆盖原轮换，在此例挤掉了原选区的有效搜索机会。选区没有找到有效联合补全，不能据此声称不存在更优方案，也不能声称已定位真实阻塞原因。

g45的3次接纳均确实来自WAIT_ANCHORED，Cmax累计下降203.768047s；但最后WAIT为640.857255s，高于初始477.485051s。第17、18轮接纳均伴随WAIT上升，进一步说明必须保留真实Cmax接纳，而不能用WAIT下降替代目标。第2轮的大改善仅改变R3路线顺序，归属和方向均未改变；g21案例则同时出现机器人转移、顺序和方向变化，均来自原联合插入动作。

g36提供了真实动态切换证据：初始无WAIT，前23轮沿用原选区；第23轮TRAVEL把Cmax降低0.084064s，却产生44.906173s等待，第24轮立即改用WAIT_ANCHORED并发生DEADLOCK。g21则在第23轮WAIT接纳后消除等待，第24轮恢复原定LOAD。失败或未改善候选的调度从未替换current。

**结论：WAIT反馈在g21、g45有真实局部收益，但本轮没有建立稳定优于GNN-V2原轮换的证据，不值得作为默认策略保留。** 两胜的收益合计210.325123s，小于两负的损失231.978070s；六例最终Cmax总和反而增加21.652947s（仅作描述统计，不是新优化目标）。相对共同初值的逐实例改善率均值由BASE的2.553206%降到WAIT的2.179314%，B32成功由114/144降到99/144，搜索时间由63.287s升到66.998s。WAIT组共接纳10次，其中9次来自WAIT重构，另1次为g36无WAIT时的TRAVEL改善；接纳次数较多仍未转化为更好的总体结果。

**本轮决策：继续使用默认关闭WAIT开关的原GNN-V2；保留开关、CSV和案例供复现，停止“有WAIT就优先覆盖”这条路线，不增加blocker识别模块，回到现有GNN-V2的父焊缝选择问题。** 不据这六个DEV继续挑种子、阈值或增加搜索轮次。

必要验证：186项相关现有及新增回归测试通过，覆盖GNN构造、LNS、初始化、方向及调度等价性；另核对12条轨迹的共同初值、q/种子、24轮连续current、严格接纳与B32次数。无WAIT保持原区及WAIT部分解为空/None的回退均有测试；正式实验中部分解失败回退实际为0次。未读取封存测试几何，未训练或修改模型权重，原V2文件保留。
